## 1. What was built

A batch leg now runs on the engine the web server runs. `run_one` (AppTest) is untouched and stays one release as the cross-check.

| piece | where | what |
|---|---|---|
| `run_paper(paper, request, deadline) -> (RunOutcome, state)` | `service/pathway.py` | The body of `run_pathway` after the input rules: build the `RunOutcome`, run `_drive`, catch a crash, stamp `seconds`. `run_pathway` now calls it; its behaviour is unchanged (107 + 8 equivalence tests) |
| `run_one_pathway(paper, mode, *, timeout)` | `batch/driver.py` | `run_one`'s twin. Same `RunOutcome`, never raises. `timeout` becomes the absolute deadline `time.time() + timeout`. A paper with no text is judged first, with `run_one`'s own verdict and message, because the service would call it `error`/`contract` |
| `ENGINE_*`, `resolve_engine`, `engine_fn` | `batch/driver.py` | Names `run_pathway` (default) and `apptest`. `engine_fn("run_pathway")` selects the service engine; anything else, including no engine, selects `run_one` |
| `run_single(..., engine=None)` | `batch/runner.py` | Without `run_fn`, takes the engine from the argument, else from the run's `plan.json`, else AppTest. Called bare it behaves as before |
| `run_batch(engine=None)` | `batch/runner.py` | `None` reads `T2PW_BATCH_ENGINE`. A fresh run stores the engine in `plan.json` (default `run_pathway`) and logs `leg engine`. A resumed run keeps its plan's engine unless one is given, and a plan from before R6 names none, so it resumes on AppTest. An unknown name exits 2 with a message and creates nothing |
| `CHILD_IMPORTS` entry | `batch/runner.py` | `t2pw.service.pathway`. The existing preflight test requires every import the driver defers to be listed; it failed until this was added |

**Why the engine travels in `plan.json`.** The child is started as `batch_run.py --single ...` and inherits no argument I may add: `scripts/batch_run.py` is outside the boundary, and `test_cli_single_runs_one_pair_and_emits_one_line` replaces `run_single` with a function that accepts no new keyword. The plan is already what the child reads (`paper_from_plan`), it makes a resumed night keep its engine, and it records which engine produced a run.

**Import cycle.** None. `pathway.py` still imports the driver inside functions only; the driver imports `pathway` inside `run_one_pathway`. A subprocess test imports each module fresh and asserts the other is not loaded.

## 8. Open questions (product owner)

**Q-R6-A. No `--engine` flag on the batch CLI.** The option exists as `run_batch(engine=)` and `T2PW_BATCH_ENGINE`, but `scripts/batch_run.py` is outside this task's boundary. A flag is about eight lines there: one `add_argument("--engine", choices=...)` and `engine=args.engine` passed to `run_batch` only (not to `run_single`, whose test replacement takes no new keyword). Options: (A) leave the environment variable (works today, documented in `run_batch`); (B) authorise the eight lines. Cost of B: one more file in the diff and one CLI test.

**Q-R6-B. `detail` of a passing leg is shorter.** Section 4. It loses the notices the Streamlit page draws (QA issue counts, the research banner). The facts behind them are in `pwml_qa.json`, `review_flags.json`, `counts` and `warnings`, which are equal. Options: (A, recommended) accept; (B) have the service export step report the same notices through the reporter, which changes `service/export.py` and the web job page; (C) rebuild the text in `run_one_pathway` from `pwml_export_result`, which copies UI wording and will drift. A failing leg's `detail` is where the kind is read; it differs only through R5 section 3, items 1 and 2 (page-only error text), which shows in neither recorded case.

**Q-R6-C. A stage that overruns is not interrupted.** AppTest bounds every interaction, so a Stage 1 or 2 call that outruns the leg becomes an in-process `timeout` row with partial artifacts. The service checks the clock between stages (R5 Q-R5-B). An overrun inside a stage ends at the parent's kill (`_timeout_row`, the outer path, with its budget block, but without the child's partial artifacts). `status` and `failure_kind` are `timeout` on both. The child's deadline is 120 s inside the parent's, so a stage must outrun that margin to be killed. Options: (A, recommended) accept and watch the first overnight run; the AppTest engine is the fallback; (B) pass a time budget into the pipeline stages (changes `pipeline/`, outside this track); (C) run `run_paper` in a thread and join with a timeout inside `run_one_pathway`: it can write the in-process timeout row, but cannot stop the thread.

**Q-R6-D. The batch calls the core of `run_pathway`, not the `PathwayRequest` wrapper.** PLAN says "calls `run_pathway` directly". The wrapper rebuilds the paper from texts (the id becomes `web:text1`, the text is stripped), scrubs server paths out of every artifact and `detail`, and returns a result without `detail`, `scope_conflicts` or `observed_context`, so a leg rebuilt from it would differ in file bytes and row. `run_paper` is that same code (`run_pathway` calls it), so the leg runs the web server's pipeline path. Option: (A, recommended) keep; (B) call the wrapper and rebuild a `RunOutcome` from the result and `run_outcome.json`: closer to the letter, loses what is listed above.

**Unverified.** No live paper was run on the new default; section 4 is a replay of two recorded cases. The first overnight batch on `run_pathway` should be paired with one `apptest` run of the same topics, as the A/B script does offline.
