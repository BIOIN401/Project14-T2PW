## 3. Things the reviewer must look at

1. **The `state=None` default differs by function, on purpose.**
   - `run_quarantine_boundary`, `freeze_canonical_payload`, `run_post_pipeline_sbml_artifacts`: `None` -> a throwaway `{}`. They cannot consult anything else: golden `test_c011` exec-extracts `run_quarantine_boundary` and `freeze_canonical_payload` into a fixed namespace (`_GLOBALS`), the stage-2 harness execs `run_post_pipeline_sbml_artifacts` in a hand-built one, and `test_c030` pins `freeze_canonical_payload`'s function-local imports to exactly `HASH_SCHEMA_VERSION`. Only builtins are safe on that path.
   - `build_rag_round_stages` / `run_rag_rounds` / `maybe_run_rag`: `None` -> `default_state()` / `default_reporter()`, i.e. whatever the app installed at import (`st.session_state`, `StreamlitReporter(st)`), else `{}` / `LoggingReporter()`. This is what keeps `test_c055::test_the_round_leaves_the_quarantine_boundary_session_record_untouched` non-vacuous: it sets `app_module.st.session_state = <dict>` and calls `app_module.run_rag_rounds(...)` without a state, and still sees the round restore its sentinels (brief: "the stubbed-streamlit tests at c055:245 must still see the writes").
   - App path: identical, because the app passes `state=st.session_state` / `reporter=StreamlitReporter(st)` at every call site and does not rely on either default.
   - **Non-app callers of the three postpipeline functions** (tests, scripts) used to write five keys into whatever `streamlit` module `postpipeline` had bound at import (a MagicMock stub in tests, or the real module, which outside `streamlit run` does not persist a session). They now write a throwaway dict. No test reads those keys on that path (grep of every `quarantine_*` session read: all are `at.session_state` in AppTests, which go through the app). This is the one observable difference, and it is the headless capability R2 exists for.
2. **`install_app_defaults` is process-global state** set at app import. AppTest re-execs the app per run, so it is re-installed with the live `st` each time. A process that imports the app and then calls the RAG service functions without `reporter`/`state` gets Streamlit behaviour, which is exactly what the base did (the code was app code using the app's `st`).
3. **Golden `test_streamlit_quarantine_boundary.py:771-788` coverage gap (R1-F1 analogue). Not edited.** The test passes unchanged: it collects `quarantine_and_close` callers over `APP_PATH` and `SERVICE_PATH` (postpipeline). The RAG round adapters now live in a third file it does not parse, so an unguarded `quarantine_and_close` added to `rag_orchestration.py` would not fail it (the moved code calls `run_quarantine_boundary`, never `quarantine_and_close`, so the assertion is still true). Widening its file set is a golden-seam edit beyond a path, so it is an open question (section 7), not done here.
4. **c055 patch-target repoints mirror R1-F3/F4.** `app_module` pops `t2pw.service.rag_orchestration` with `postpipeline`; `offline_stages` patches the RAG module's four stage names when it is cached and drops it afterwards when it was not; `_rebind` re-points the four stage names on the RAG module instead of the app (`app.quarantine_and_close` is unchanged); the `maybe_run_rag` and `build_and_save_draft_graph` patches target the RAG module. Same values, same stubs.
5. **`OWNED_FLOOR` 2571 -> 1440** in `test_c060a` is a line-number locator, as in R1 (flagged (!) in section 4). The selection is the same two merge sites and the same one gate-module import before site 0.
6. **`test_rag_triage_orchestration` patches `rag_config` via `monkeypatch.setitem(app.maybe_run_rag.__globals__, ...)`**, i.e. the globals of the very function the test then calls. `setattr(<module>, ...)` on a freshly imported module could miss: several files in the same process delete and re-import `t2pw.*` modules, and the test's `app` is bound once at collection.
7. `RagOrchestrationResult.__module__` is now `t2pw.service.rag_orchestration` (it was `t2pw.app.streamlit_app`, or `__main__` under `streamlit run`). Nothing pickles it or reads its module name (grep).
8. `test_rag_seed_entity_reimport::test_the_orchestrator_passes_the_merge_base_to_conform` is a pre-existing failure (base 2d). It still fails, now one line earlier: the `conform_rag_additions_for_merge` call it looks for in `streamlit_app.py` moved to `rag_round_merge`, so `len(conform_calls) == 1` fails instead of the later `next(...)` StopIteration. Same node id, so the failing-node set is unchanged. Not repointed: it does not pass either way, and repointing would not change that.
9. CRLF: every edited file keeps CRLF; the three new files are CRLF like their neighbours. Unused imports left in `streamlit_app.py` (no cleanups).
