## 2. Replay design

There are three boundaries. Each is patched at the one place every caller already routes through, so no bound name in an importer is missed:

| boundary | patched at | why this one place suffices |
|---|---|---|
| LLM | the **instance** attribute `t2pw.llm.client._client.chat.completions.create` | `chat`, `chat_detailed` and `chat_with_tools` read the module global `_client` at call time. `t2pw.stoich.agent` binds the same object (`from t2pw.llm.client import _client`). OpenAI's `chat` and `completions` are cached properties, so the instance attribute shadows the method for every holder. Every importer that bound `chat` by name (pipeline, preprocessor, curator, gap_resolver, audit) therefore routes through it |
| HTTP | `requests.Session.request` (class) | `map_ids.HttpClient`, the per-thread enrichment clients, `stoich.agent._SESSION` and bare `requests.get` all end there. No urllib or httpx call exists on this path |
| PathBank DB | `map_ids.PathBankDbResolver._query` | it is the only method that touches the connection (`_ensure_connection` is only called from it). The replay never connects |

**Modes:**
- **record** calls through and saves the pairs.
- **replay** serves recorded answers in recorded order per key. Any unrecorded request, or one ask more than was recorded, raises `ReplayMiss` and is listed in `misses`. Every non-loopback `socket.connect`, `connect_ex`, `create_connection` and `getaddrinfo` is refused and listed in `refused`. Loopback stays open, because AppTest's event loop on Windows uses a loopback `socketpair`.

**Errors:**
- HTTP errors are recorded and re-raised as the same `requests.exceptions` type, so the retry ladders replay too.
- LLM transport errors are not stored; the client's own retry hides them. They are counted as `live_llm_errors`, and this fixture has 0.

**Environment:**
- Every `T2PW_`, `RAG_`, `LLM_`, `OPENROUTER_`, `PATHBANK_`, `NCBI_`, `LMSTUDIO_` and `LOCAL_` variable is cleared.
- The fixture's pinned non-secret values are then set, and `dotenv.load_dotenv` becomes a no-op, so neither a `.env` (client.py loads with `override=True`) nor the shell can steer a replay. The pinned set is the `.env` minus secrets and minus `RAG_*`.
- Forced: `T2PW_OFFLINE_CURATOR=1`, `T2PW_SPECIES_LLM=0`, `T2PW_SPECIES_NCBI=0`, `RAG_ENABLED=0`. RAG acquisition uses urllib against PubMed and an embedding endpoint, which the cassette does not cover.
- Replay gets placeholders for the API key and the DB host/user/password, plus `LLM_CALL_SPACING=0` (a sleep only).

## 3. Keying (what is keyed, what is ignored)

Each key is the sha256 of a canonical JSON (`sort_keys`, compact).

- **LLM:** every `create()` kwarg except `model`, `timeout`, `extra_headers`, `extra_query` and `extra_body`. What is keyed: messages (pydantic messages via `model_dump(mode="json")`), temperature, max_tokens, response_format, tools, tool_choice. The key is model-agnostic; the answering model is kept in the stored response only.
- **HTTP:** method, the fully prepared URL (`params` merged in) and the body (`data`/`json`). Headers, timeouts, `verify` and the session are ignored. The values of `api_key`, `apikey`, `key`, `token`, `access_token`, `email` and `tool` query parameters become `<redacted>` in the key and in storage.
- **DB:** SQL text plus params, exactly.

Repeats: one key holds an ordered list of answers. For example, the three Stage-1 draws ask the identical request at temperature 0 and get three different answers.

Pinned by `test_keying_ignores_the_model_and_the_timeout_only`.

## 4. Secret handling and the scan

**Stored:** no request headers, no `Set-Cookie`/`Cookie`/`Authorization` response headers, secret query parameter values redacted, and DB error strings scrubbed of the configured secret values.

**Two layers of protection:**
1. At write time, `assert_no_secret_values` refuses to write a fixture containing the value of any `SECRET_ENV` variable taken from the real `.env`. The error names variables, never values. The assembled fixture passed it.
2. In the test, `test_fixture_holds_no_secrets` scans the committed fixture for secret shapes: OpenRouter key, bearer token, authorization or cookie header, non-redacted api_key or token parameters, any e-mail address, `PATHBANK_DB_HOST/USER/PASSWORD`, password fields, and OpenRouter's `HTTP-Referer`/`X-Title` headers. It also checks that every pattern catches a planted example. It passes.

The evidence logs were also scanned for every secret value and for key or e-mail shapes before committing: clean. The only `.env` value that appears in them is `NCBI_TOOL`, whose value is the project folder name and shows up inside paths; it is not a secret.

## 8. The blocking finding: wall-clock control flow in the audit loop (needs-decision)

In `src/t2pw/service/postpipeline.py` (moved in R1, unchanged), the audit loop sets `audit_started_at = time.time()` (line 920). It then branches on `time.time() - audit_started_at > timeout_seconds` at lines 940, 976 and 1131, and lowers `candidate_count` to 1 when fewer than 120 s remain. The timeout comes from the sidebar's "Audit repair timeout", default **240 s**.

**Live run** (call order in the transcript plus the progress lines in `a2-seg02.log`):
- The audit started at about +60 s. Round-1 candidates (temperatures 0.0, 0.14, 0.28) ran until about +165 s.
- Round 1's gap resolution (planner, selector, location resolver, enrichment agent, with HTTP and DB) ran until about +311 s, roughly 250 s after the audit started.
- At the round-2 check the elapsed time exceeded 240 s, so the loop stopped with `stop_reason="timeout"`.

**Replay:**
- Stage 0-2 is faithful: every stage file at post-pipeline start has the same sha256 in live and replay. The exception is `extraction_boundary_report.json`; it is not compared and not in the payload.
- The round-1 audit records are identical, field by field (`audit_iteration_summary.json`, live vs replay).
- But round 1 finishes in seconds, so the loop starts **round 2** ("Previous attempt unresolved: errors=1, ... gap_payload_changed=True"). Round 2's requests were never recorded: 4 LLM, 12 HTTP and 1 DB misses.

Consequence: any recording through this loop pins the path its live latency happened to take. No replay can follow that path without a clock, which is a real nondeterminism in behaviour. The only other clock reads on this path are rate-limit sleeps (`map_ids` NCBI spacing, enrichment lanes), which are timing only.
