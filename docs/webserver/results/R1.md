## 3. Things the reviewer must look at

1. **Logger name.** Base: `logging.getLogger(__name__)` in the app, i.e. `t2pw.app.streamlit_app` when imported (tests, `-m`), but `__main__` under `streamlit run`. The moved code (the `_record_*` helpers) now logs under the literal `"t2pw.app.streamlit_app"`. Identical when the app is imported; under `streamlit run` those debug lines change logger name from `__main__` to `t2pw.app.streamlit_app`. The app keeps its own `logger` for staying code. No test captures this logger. A pure move cannot keep `__name__` semantics; this is the closest. Open question 1.
2. **Patch-by-source-module no longer reaches the moved code.** AppTest re-execs the app script each run, so the app's from-imports re-bind to whatever a test patched on `t2pw.mapping.*`/`t2pw.curation.*`/`t2pw.paths`. The service module is imported once and cached, so its from-imports are bound at first import. In production nothing patches, so behaviour is identical; for tests it is the cause of rows 4, 14-16 above. It was masked in single-file runs (first import happened under the patch) and showed as an order-dependent failure when files ran together. Any future test patching a name the moved code uses must patch `t2pw.service.postpipeline`. Open question 2.
3. `OWNED_FLOOR` row above (a number, not a path).
4. `run_quarantine_boundary` still writes `st.session_state`; the service module imports `streamlit` (R2 removes it). `src/t2pw/service/pathway.py` and `__init__.py` untouched.
5. Unused imports now remain in `streamlit_app.py` (not cleaned: "no cleanups"; tests may reach names through the app).
6. CRLF: all edited files keep CRLF; the new module is CRLF to match its neighbours.
