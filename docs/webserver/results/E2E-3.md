# E2E-3 phase 1: the real site in a real browser

Operator: test run only. Nothing under `src/`, no template and no test was edited.
Branch `ws/E2E3-browser`, base `518339dd`. Phase 2 (one real paper) was not started.

## Verdict

**The site cannot take a submission from Chromium as shipped.** Every form POST gets a 403
"Request blocked" (finding 1). Once that one defect is stepped around in the test, the rest of the
walk (form, validation, HTMX polling, result pages, downloads, keyboard, phone, dark mode, rate
limit) works, with the rough edges listed below. Run 5 of the driver: 135 checks passed, 2 failed
(the 403 itself, and a spec question: no pasted-text mode).

## What was run

* `drive.py`: ONE script under `bounded_run.py --heavy-lock E2E3`, run with the throwaway venv
  `C:/t/e2e3-venv` (playwright 1.64.1, Chromium 156 headless shell). It starts uvicorn
  (`--factory t2pw.web.app:create_app_from_env`, 127.0.0.1, random port) and the worker
  (`python -m t2pw.web.worker --run-fn fake_run:run_pathway --poll 1`), walks the site, writes
  `results.json` and `screenshots/`, then stops both. The servers get a scrubbed environment (no
  `.env`, no key; `T2PW_RATE_KEY_SECRET=dummy-e2e3-not-a-secret`). `PYTHONPATH` points at this
  worktree's `src/`.
* `fake_run.py`: the fake run function. The pathway name picks the result: success (pass,
  `release_ready`, PWML, PNG, 5 reports), review (`review_required`, 2 warnings), fail (`fail` /
  `contract`, one report, no PWML), flaky (attempt 1 `error`/`network`, retried, attempt 2 passes),
  anything else instant success. Each real run sleeps 14 s so the status page has time to change.
* `run.sh`: the wrapper loop (retries only on exit 95).
* The final evidence: `E2E-3-wrapper.json` (wrapper report, `FINAL SURVIVING COUNT : 0`),
  `wrapper_stdout.log`, `results.json` (every check, timeline, console, network), `uvicorn.log`,
  `screenshots/` (62 files, 5.5 MB total evidence folder), `run1-origin-403/` (the first run, with no
  shim at all: the 403 everywhere).

## Finding 1 needs a test shim; read this before the numbers

Chromium's form POST carries `Origin: null` (see finding 1), so with the site as shipped no
submission works and nothing after the form could be reached. From the second `S3` case on, the
driver injects `<meta name="referrer" content="same-origin">` into each page it loads. That makes
Chromium send the real Origin, which is what a corrected server would receive. It changes no server
code and no request. Everything marked as tested "with the shim" used it. The raw, unshimmed 403 was
captured first in every run (`08a-bad-empty-server-RAW-403.png`, check `S3b-raw`).

* **Organism search:** typing 1 or more characters sends one debounced `/organisms` request
  and fills the datalist (30 options for "escher"; `zzzzqq` gives none); the chosen value sticks after
  blur; no JS error. (The headless browser draws no native popup, so ArrowDown+Enter could not be
  checked; a pick was simulated by setting the exact label.)
* **Bad input, with the shim** (every one keeps mode and field values, shows the message beside the
  field or in the red box): empty, name over 200 chars, bad PubMed IDs (names `abc`, `12-34`), a

* **Good job, with the shim:** 303 to `/job/<32 hex>`; four pathways queued. The HTMX panel polled by
  itself (every 10 s, first poll seen with the worker still off), swapped `#job-items` 7 times, never
  reloaded the page (a marker on `window` survived), and went queued -> running -> done / review
  required / failed / (retry) done. Polling stopped once everything finished (0 further `/status`
  requests in 13 s). A second tab on a queued item's result page refreshed itself (`<meta refresh>`)
  to "Done" (`16`, `19`). Timeline in `results.json`, shots `15`, `17-*`, `18`.
* **Result pages** (`20`, `21`): success, review_required (warning banner, warnings, PWML), failed (no
  PWML link, plain explanation, only its report), retried (attempts table shows the retry). Every link
  returned 200 with the right type: PWML `application/xml`, PNG diagram renders in the page, JSON
  `application/json`, CSV `text/csv`, TXT `text/plain`, all `attachment` with the file's name and
  `Content-Security-Policy: sandbox; default-src 'none'`. Clicking Download PWML in the browser saved
  the right bytes for items 1, 2 and 4. 404 for item 9, the PWML of a failed item, a non-existent
  job, `/nope`, `..%2F` in a report name and `request.json`; all render the styled error page.
  `/jobs/<sid>` redirects to `/job/<sid>`.
* **Help, Examples, About:** every nav link works, `aria-current` is right, every internal link on
  the four pages returns 200, no external links. Skip link is the first Tab stop and works.
* **Keyboard only** (shim): 16 Tab stops, all with a visible focus ring (3 px blue outline); the
  form was filled and submitted with the keyboard; arrow keys switch the mode (`40`-`43`).
* **Phone (390 px) and dark mode**, 4 contexts x 8 pages: no horizontal page overflow; contrast
  check (every text node, 4.5 / 3:1) found 0 low-contrast nodes (`50-*`). The wide attempts table

* **Rate limit** (shim): after 5 accepted submissions, the 6th is a 429 with the red box "You have

  kept, `Retry-After: 86302` (`60`).
* **Real PDF upload** (a generated 1-page PDF, shim): accepted; the job page says "1 PDF file" (`45`).
* **Console and network over the whole walk:** zero JS errors, zero failed requests. 14 console

## Bugs and rough edges

Severity: **B** blocks launch, **S** should fix, **C** cosmetic.

1. **B. Home / every submit. A real Chromium form POST is rejected 403 "Request blocked: This form was
   sent from another site".** `app.py` sets `Referrer-Policy: no-referrer` on every response. Under
   that policy Chromium sends `Origin: null` on a same-origin form POST (captured:
   `origin: null`, `sec-fetch-site: same-origin`, no `referer`, `host` correct). `_cross_site()` reads
   the Origin host as `""`, which is not the site, and refuses. TestClient never sends `Origin: null`,
   so the tests could not see this. Should happen: a visitor's own form post is accepted. The
   request does carry `Sec-Fetch-Site: same-origin`; the product owner / implementer picks the fix
   (trust that header; or allow `Origin: null` only with `Sec-Fetch-Site: same-origin`; or send
   `Referrer-Policy: same-origin`, which still sends no referrer to other sites). Not tested: Firefox
   and Safari (they may differ). Shots: `08a-bad-empty-server-RAW-403.png`,
   `run1-origin-403/08-bad-empty-server-403.png`; check `S3b-raw`; `results.json` `notes.post_headers`.
2. **B (content). Help, Examples, About and the footer on every page show unfilled placeholders:**
   "[TODO for the product owner: how long jobs and uploads are kept.]" (Help), "[TODO ... 3 to 4
   curated, verified examples ...]" (Examples), two "[Placeholder ...]" blocks (About), and
   "[Citation placeholder: added on publication.]" / "[Lab credit placeholder.]" in the footer. Known
   (Q-W6-5); listed because a visitor sees them. Shots `31`, `32`, `33`; `results.json`
   `notes.placeholders*`.
3. **S. Home, organism box. Search matches the scientific label only, so common names find nothing.**
   "mouse" -> 1 junk hit (`Candidatus Arthromitus sp. SFB-mouse-Japan`), "yeast" -> 0, "E. coli" -> 0,
   "e coli" -> 0, "human" -> a species literally labelled `human` first. The data has `common_name`
   for 202 species (I did not check which species; the search never reads the field).
   "rat" returns Rattus norvegicus then Veillonella ratti and unrelated substring hits. The list is
   cut at 30 with no sign it is cut ("escherichia coli" lists 30 strains). Should happen: a biologist
   typing "mouse", "human", "yeast" or "E. coli" gets Mus musculus, Homo sapiens, S. cerevisiae,
   E. coli. Evidence: `organism_search_probe.py` and `.out.txt`.
4. **S. Job page and result page, Attempts table. A quality-gate failure is described as
   "Failed (an unexpected problem occurred)".** The headline says "The extracted pathway did not pass
   the quality checks"; the table row for the same attempt contradicts it. Cause: `_kind_text()` has no
   text for `contract` / `ambiguous_review_scope` / `no_reactions`. Shots `21-result-2-fail-expanded`,
   `50-phone-dark-job`.
5. **S. A rejected upload costs a daily submission slot.** The `.txt` upload was refused ("not a PDF")
   but counted: 4 later accepted submissions plus it used all 5, and the next try was a 429. Known
   shape (W8 order: rate limit before the upload save), confirmed from the browser. A typo costs a
   fifth of the day's allowance. Shot `13-bad-non-pdf`; `rate_tries` in `results.json`.
6. **S (question). No "pasted text" input mode.** The site offers Pathway name / PubMed IDs / PDF
   files. My brief listed pasted text. If text paste is intended for launch it is missing; if D-decisions
   dropped it, ignore. `notes.modes_offered`.
7. **C. Field-level errors have no summary or focus move.** With only field errors (bad PMIDs, mistyped
   organism, bad email) there is no red box at the top; the page re-renders at the top and the error may
   be in row 4 below the fold. Shot `11-bad-organism-email`. Suggest an error summary at the top.
8. **C. Phone, job page.** The Outcome column of the Attempts table is cut off inside its scroll box
   ("Failed (ar ...") and the job URL in the blue box breaks inside "http://". No page overflow.
   Shot `50-phone-dark-job`.
9. **C. Name and organism fields have no `maxlength`.** A 250-character name is accepted by the
   browser, rejected by the server, and the redisplayed field is silently cut to 201 characters.
   Shot `09-bad-name-too-long`.
10. **C. The "Retrying automatically" state was never seen on screen.** The retry takes seconds with the
    fake run and the poll is every 10 s, so it falls between polls (`saw_retrying_text: false`). Only
    the attempts table shows the retry afterwards. With real runs (minutes) it will show; not a defect.
11. **C. Dark mode follows the system only** (no manual switch). Fine for launch; noted.

## Dead ends and incidents

* Run 1: no shim; all submissions 403 (kept in `run1-origin-403/`).
* Run 2 (not kept): tried setting `Origin` with `route.continue_(headers=...)`; Chromium ignores it.
* Runs 3 and 4 (not kept): tried re-serving every HTML response through `route.fetch` with
  `Referrer-Policy: same-origin`. Forms then worked but browser file uploads arrived as "is empty"; a
  raw (urllib) upload of the same PDF worked. Interception is the probable cause (a harness artifact,
  not a site bug), so the shim was changed to the `<meta name=referrer>` injection, with no request
  interception, and the uploads then behaved correctly.
* A harness slip, not a site bug: my first organism check used Playwright `wait_for_function`, which
  runs `eval()` and is blocked by the site's own CSP (`script-src 'self'`). It threw page errors and
  made the first two "typing finds nothing" results false. Replaced by fixed waits; the site passes.
  (It does show the CSP is enforced.)
* The shared heavy lock was held by R26 (`farnesol_research` recordings) through about 55 minutes of
  retries in total (`WRAPPER_EXIT 95` loop, never started a child while it was held). Several wrapper
  loops ran out their try counts; each re-run was by hand.
* Process slip: one `python -` with an empty heredoc (a mistake in a sed command line) waited on
  stdin and was stopped with TaskStop after the tool moved it to the background. It touched nothing;
  a process scan afterwards found no leftover.
* Windows console encoding made one print of a `U+2190` arrow throw; `sys.stdout.reconfigure(utf-8)` fixed it.

## Open questions

**Q-E2E3-1. How should the Origin check treat `Origin: null`?** (a) Trust `Sec-Fetch-Site: same-origin`
(all current browsers send it). (b) Change `Referrer-Policy` to `same-origin`. (c) Both. Cost: a few lines in
`app.py` plus a test that posts `Origin: null` with and without `Sec-Fetch-Site`. Needs a decision
because the check is a W8 abuse control. This blocks every submission until fixed.

**Q-E2E3-2. Common names in the organism search** (finding 3): (a) search `common_name` too and rank
exact label / common name matches first; (b) leave as is and say "use the scientific name" in the hint.

**Q-E2E3-3. Pasted text mode** (finding 6): keep three modes, or add text?
