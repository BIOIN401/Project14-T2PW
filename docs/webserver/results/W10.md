## 2. Routing table

| input | how it is recognised | what the visitor gets | LLM? | job? |
|---|---|---|---|---|
| pathway name, PathBank has it ("TCA cycle", "enterobactin biosynthesis E. coli") | no identifier, short; organism split off by exact organism-list match (label, common name, "E. coli" abbreviation) after " in "/" of "/","/"(" or as the last 1-3 words | the PathBank pathway page: name, organism, category, PW and SMP ids, "Open in PathBank", diagram (local mirror) and PWML download, similar names, "Generate from literature instead", PathBank credit | no | no |
| pathway name, only similar PathBank names ("glycolysis in Saccharomyces cerevisiae", typos) | as above; best score < 0.99 | up to 3 PathBank choices, plus up to 3 for other organisms, plus "Generate from literature instead" | only if the pathway part is 4+ words or has "?" | no |
| sentence ("how does baker's yeast make ergosterol?") with no deterministic hit | `wants_llm` | the LLM extracts `{kind, pathway_name, organism, identifiers}`, then the PathBank lookup runs again | yes, once, rate-limited (30/visitor/window) | no |
| PMID, PMCID, DOI, PubMed/Europe PMC/doi.org URL | regexes (`PMID: n`, a bare list of numbers, `PMCn`, `10.x/y`) | the run form prefilled with PMIDs (PMCIDs and DOIs converted through the NCBI ID converter; an unconvertible id is listed with what to do) | no | after the visitor presses "Start the run" |
| pasted passage | >= 400 characters with 2+ sentence ends, or >= 400 characters with no identifier | the run form with the text | no | after "Start the run" |
| other URL | `https?://` or `www.` with no paper id in it | "T2PW cannot read a web page directly; give the PubMed ID, PMCID or DOI, paste the text, or upload the PDF" | no | no |
| no PathBank match | empty search result | the run form in name mode (the existing name-mode literature retrieval: `inputs.resolve_name` -> Europe PMC / NCBI), "No curated PathBank pathway matched" | no | after "Start the run" |
| PathBank index missing on the server | `PathBankIndex.available` false | the name-mode run form with a notice | no | after "Start the run" |

The run form follows the same rules as `/submit`: pathway name and a listed organism in every mode (PO ruling
Q-BR-1), consent on by default, optional email, the same rate limit, queue cap and job store. One job per run.

## 3. PathBank data source: decision and evidence

**Decision: the PathBank MySQL database, frozen once into a local SQLite index; diagrams and PWML from a local
mirror of PathBank's attachment store; pathbank.org only as an outgoing link.** Runtime never touches the DB or
the network for a PathBank answer.

| option | evidence | verdict |
|---|---|---|
| A. Query the PathBank DB per search | Works (new host since 2026-11-18), but every public search would hold a DB connection; the future server gets its own read-only user, and the W2 pattern (freeze to a file, never query at runtime) already exists | used **once**, by `export_pathbank_index.py`, not per request |
| B. PathBank's public download list from pathbank.org | Every pathbank.org URL answers **403 with a Cloudflare "Just a moment..." challenge** to curl (plain and Chrome UA), WebFetch and headless Edge (`evidence/W10/pathbank_org_probe.txt`). The list, the per-pathway PNG/SVG/PWML and the downloads page (licence text) cannot be fetched by a server | rejected: not fetchable |
| C. Local SQLite index built from the DB (chosen) | 11 s to build, **520,748** public pathways (`named_for_type='Pathway' AND private_pathway=0 AND export=1`), 199,858 distinct names, 81.6 MB; a search takes 0.03-0.12 s on it (`evidence/W10/search_probe.out`) | chosen; file gitignored, rebuilt per server |

Facts from the read-only probes (`evidence/W10/db_probe.out`, scripts in `evidence/W10/scripts/`, no host/user printed):
- `super_pathway_visualizations` has 538,322 rows: 520,748 public exported pathways, 16,271 public not exported,
  640 private, 663 contexts. All public exported rows have `pw_id` and `smpdb_id`. `parent_id` is 0 for every one.
- PW accessions are read from `spv.pw_id` (never `pathways.id`), as the project memory says.
- Names repeat across species (e.g. "Glycolysis" 146 species, "TCA Cycle" 67); the index keeps one row per pathway
  and one row per distinct normalised name, and a search returns one pathway per name: the requested species', else
  the lowest PW id (the curated original: TCA Cycle PW000779, Alanine Metabolism PW000001).
- PathBank stores **no pathway synonyms**. `SYNONYMS` in `web/pathbank.py` is a 4-group hand list (TCA / citric acid /
  Krebs / tricarboxylic acid cycle; glycolysis / Embden-Meyerhof; pentose phosphate pathway / shunt; urea / ornithine
  cycle). Open question 3.
- Names include user practice copies with `export=1` ("TCA cycle with mistakes" PW696612, "TCA Cycle - Practice").
  They rank below the originals (higher PW ids) but can appear as choices. Open question 4.
- Diagram and PWML files are Paperclip attachments (`*_file_name` columns): the DB holds their names, not their
  bytes (301,163 rows have a PWML attachment). The bytes live in PathBank's attachment store, laid out as
  `<attachment>/<PW>.<ext>` (`full_vector_images/PW000779.svg`, `simple_vector_images/...`, `pwml_markups/PW000779.pwml`).
  The page uses the full-colour SVG (what pathbank.org shows), else the simple one. A 16-PWML / 21-SVG
  copy of that store is at `C:/t/vis-ref/super_pathway_visualizations/...` (used by VIS-3); `T2PW_PATHBANK_FILES`
  points the server at such a mirror. PathBank's SVGs are self-contained (all art as `data:` URIs), so the page shows
  PathBank's own diagram; with only a PWML the server renders it once with VIS-3's `render_pwml` and caches the PNG.
  With neither, the page says so and links to PathBank. Open question 1.

Credit on every PathBank page: "Pathway data and diagrams: PathBank (Wishart Lab, University of Alberta). Please cite
PathBank when you use this pathway." The licence could not be read (Cloudflare); open question 2.

## 6. Dead ends and slips

- **pathbank.org (option B)** cost three probes (curl, WebFetch, headless Edge): all Cloudflare challenges. Not retried
  with cookies or a real browser session: a server must not depend on solving a bot challenge.
- **`super_pathway_visualizations.parent_id IS NULL`** was my first guess for "original, not species-propagated": it is
  0 on every row, so it cannot separate originals from copies. The lowest PW id per name is used instead.
- **Organism ties.** The first `find_organism` preferred the shortest label: "human" picked the species labelled
  `Homo` (id 196) and "yeast" picked *Candida glabrata*. PathBank's species table has several junk rows with those
  common names (a species labelled "human", "Carlos Mejia" with common name Human). Now: has-pathways first, then the
  lowest species id (Homo sapiens 1, S. cerevisiae 18), marked `ponytail:`.
- **`_page(request, name, ...)`**: the first focused run failed 10 of 47 new tests because the run form passed a
  context key `name`, which collides with `_page`'s template-name parameter. Renamed to `pathway`
  (`evidence/W10/logs/focused1-failed-name-collision.log`). Existing web tests passed in that run too.
- **Optional name/organism for PMID/text runs.** I first made them optional on the run form, then found PO ruling
  Q-BR-1 (pathway name and organism required in every mode, `results/BR.md` § Q-BR-1) and aligned the form with
  `/submit` before the code commit.
- **Rule slip, reported.** While editing a probe I mistakenly ran `python.exe -I - </dev/null` (a stdin interpreter
  invocation, forbidden by the first rule). It hung for 120 s; I stopped the task with TaskStop and confirmed with
  `Get-CimInstance Win32_Process` that no python process with that command line survived. No other stdin interpreter
  call was made; every later script was written to `C:/t/ws-search-work/` and run by path.
- **Live server PID.** `live.sh` (first run) took `$!` from Git bash, which is an MSYS PID; `taskkill` answered "process not found" and the uvicorn server (Windows PIDs 407392 and child 403828, command line `live_app.py`) kept running after the script. I found it by its command line and killed that tree by PID about two minutes later, while the same bounded job was still in its suite step; the job's final report says 0 survivors. `live2.sh`/`live3.sh` read `/proc/$!/winpid` and report `survivors: 0` themselves.
- **Edge cache.** `live2.sh` reused the first run's Edge profile, so the TCA screenshot after the full-colour fix still showed the old SVG (the server log has no diagram request). Re-shot with a fresh profile (`live3.sh`).

## 7. Open questions for the PO

**Q-W10-1. Where does the server get PathBank's diagrams and PWML?** The DB holds only attachment file names;
pathbank.org blocks servers. Today the page shows PathBank's diagram only for pathways in a local mirror
(`T2PW_PATHBANK_FILES`), else a link to PathBank.

| option | cost |
|---|---|
| A (recommended) | Mount or rsync PathBank's attachment store (`full_vector_images/`, `pwml_markups/`) read-only on the T2PW host; the lab owns both servers. Zero code. Size unknown (301k PWMLs + SVGs; likely tens of GB) |
| B | Mirror only a subset: the originals (lowest PW id per name, about 200k) or only the most-viewed few thousand. Zero code; a sync script |
| C | Ask the PathBank admins to allowlist the T2PW server's IP in Cloudflare, then fetch and cache per pathway on first view. Small code change (a fetch + cache in `/pathbank/{PW}/diagram`) |
| D | Keep link-only for pathways without local files (today's behaviour). No cost; weaker demo |

**Q-W10-2. PathBank licence and credit line.** The downloads page (licence/terms) could not be read. The page credits
"PathBank (Wishart Lab, University of Alberta)" and asks users to cite PathBank. Please confirm the wording and the
citation to show (e.g. the PathBank 2.0 NAR database-issue paper).

**Q-W10-3. Pathway synonyms.** PathBank has no synonym table; 4 hand groups cover TCA/Krebs, glycolysis,
pentose phosphate and urea cycle. Options: (a) keep the hand list and grow it from search logs (cheap); (b) let the
LLM normalise every query that has no exact hit (one LLM call per such search: cost and latency); (c) ask PathBank
curators for a synonym list.

**Q-W10-4. Practice and replica pathways.** Exported public rows include curator practice copies ("TCA cycle with
mistakes" PW696612, "... - Replica", "... - Practice"). They rank below originals but can appear as choices. Options:
(a) leave them; (b) exclude names matching practice/replica/mistakes/test in the export (one SQL clause, may drop a
real pathway); (c) ask PathBank to un-export them.

**Q-W10-5. LLM budget for the router.** At most 30 router calls per visitor per rate window (the submission window),
each bounded at 25 s, model `OPENROUTER_SEARCH_ROUTER_MODEL` if set, else the default model. Set a cheap fast model
for this variable on the server? A reasoning model wastes seconds here.

**Q-W10-6. Request-path network calls.** `app.py` said "nothing here resolves a PMID or calls an LLM". The search adds
two bounded exceptions (one LLM call for a sentence-like query, one NCBI idconv call for a PMCID/DOI). Accept, or
move both into the worker (then a PMCID/DOI search can only show "we will resolve this when the job runs", and a
sentence query cannot show a PathBank answer at all)?
