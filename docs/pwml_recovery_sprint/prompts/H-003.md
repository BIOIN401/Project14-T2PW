THE DEFECT -- measured, not inferred
  Reported by the closeout reviewer of 2b786aa..1c2dbee, on its own run:

    UnicodeEncodeError: 'charmap' codec can't encode '�'
      at docs/pwml_recovery_sprint/evidence/bounded_run.py:507

  Mechanism, confirmed by reading the source:

    :497-510  _drain() reads the child's log with errors="replace" -- which can
              itself INTRODUCE U+FFFD -- then does sys.stdout.write(chunk).
              On a console whose encoding is cp1252, writing U+FFFD (or any
              non-cp1252 character the child emitted) raises UnicodeEncodeError.
    :510      the except clause catches OSError ONLY. UnicodeEncodeError is a
              ValueError, so it is NOT caught and propagates.
    :696-698  the --json cleanup report is written AFTER report.render(), on the
              normal return path of main(). An exception that escapes the wait
              loop skips it.

  Consequence, and this is why it is a G11 defect rather than a cosmetic one:
  the child's cleanup `finally` still runs, so processes are reaped -- but NO
  --json report is written, so the run is UNCERTIFIABLE. Under G11 a job with no
  cleanup report cannot be claimed as evidence. A job can therefore be killed by
  its own wrapper and leave no record, purely because the child printed a
  character the console cannot encode.

  This has already cost real work: the closeout reviewer discarded that run and
  re-ran under PYTHONIOENCODING=utf-8. The workaround must not be the fix -- the
  wrapper cannot depend on the developer's console configuration.

OBJECTIVE
  Arbitrary child output must never be able to crash the parent-side drain, and
  a valid writable --json destination must receive a cleanup report on every
  exit path.

IMPLEMENT -- all seven properties must hold
  1. Arbitrary child output cannot crash the parent-side drain on a restricted
     console encoding such as cp1252. Handle the encoding at the point of
     forwarding -- do not assume a UTF-8 console, and do not mutate global
     interpreter state as the fix.
  2. Cleanup still runs on EVERY exit path: success, nonzero, timeout,
     cancellation, KeyboardInterrupt, SystemExit, and any other exception --
     including one raised inside the drain itself.
  3. A valid writable --json destination RECEIVES the cleanup report even if
     console forwarding encounters unencodable text. Write it in a finally, or
     otherwise guarantee it before any exception leaves main().
  4. Exit classification and the child's REAL exit code remain correct. A drain
     failure must not be reported as `completed`, must not mask a nonzero child,
     and must not invent a timeout.
  5. Cleanup remains restricted to the job's OWNED process tree.
  6. NO global process termination is introduced. taskkill /IM, pkill and any
     kill-by-image-name remain permanently forbidden.
  7. If the --json destination is itself unwritable, that is a distinct and
     reported condition -- not a silent skip, and not a crash that loses the
     cleanup result.

  Keep the change proportionate. This is a targeted repair of a specific defect,
  not a rewrite of the wrapper.
