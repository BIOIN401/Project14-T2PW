WHY THIS EXISTS
  H-004 was required to make G11 auditable and did so, but two required properties
  could only be delivered from inside CleanupReport, which was H-003's file. H-004
  refused to reach for it -- correctly, and its reviewer ruled the refusal the single
  most important judgement call on that branch. The refusal left two real gaps:

  1. NO SCHEMA VERSION. D-018 requires "report-schema version, if one exists". None
     exists. H-004 versioned its own SPECIFICATION (G11_SPEC_VERSION = 1) as a
     substitute and said so plainly, but a committed artifact cannot state which
     report schema produced it.

  2. NO WRAPPER BUILD IDENTITY. No field names the WRAPPER -- `command` names the
     CHILD. [S8]'s self-reference obligation requires every result to state which
     wrapper build produced it, and today the artifact cannot answer.

     H-004's README offers git archaeology as a substitute -- `git log -1 -- <report>`
     to the commit, then the wrapper in that tree -- and honestly labels it "an
     inference from the tree, not proof from the artifact". Its reviewer then found
     the disclaimer UNDER-ENUMERATES the failure modes. Confirmed missing:
       - CROSS-CHECKOUT EXECUTION. An agent with both a main checkout and a worktree
         can run one tree's wrapper while committing on the other's branch. The
         archaeology then names a file that was never executed.
       - REBASE / SQUASH rewriting the commit `git log -1` resolves to.
       - A STALE WRAPPER run before the commit (this one IS named today).

IMPLEMENT
  1. Add a report SCHEMA VERSION to CleanupReport and to the --json output. Choose
     the bump discipline and state it: what change forces a bump, what does not.
  2. Add a WRAPPER BUILD IDENTITY sufficient to establish which wrapper implementation
     produced the artifact. It must be derived from the RUNNING wrapper -- not from
     the tree, not from git, not from an environment variable a caller can set. A
     content hash of the executing module is the obvious candidate; if you choose
     something else, justify it against the three failure modes above.
  3. Correct the g11 README disclaimer so it describes the PRESENT state accurately:
     that existing artifacts cannot prove their wrapper build, and that the archaeology
     substitute fails on cross-checkout execution, on rebase/squash, and on a stale
     wrapper. Once the field lands, say which artifacts have it and which never will.

  - The child's real exit code, or exit classification.
  - Any G11 RULE. You are making an existing rule provable, not rewriting it.
  - No global termination. `taskkill /IM` and `pkill` remain permanently forbidden.

  Reports already committed under evidence/g11/ were produced before these fields

  distinguishable from one produced before; that is the intended outcome and it is
  the honest one. DO NOT BACKFILL -- a reconstruction is not evidence of the
  original run.
