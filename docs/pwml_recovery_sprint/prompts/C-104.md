
reverting `deepcopy(dict(...))` to `dict(...)`, came back GREEN.** A shipped fix with no proof.

**Stakes are low and you must not inflate them.** A shallow copy cannot produce a wrong number. It
can only let a caller corrupt in-memory state, and nothing in the tree mutates `to_dict()` output
today. This is a guard against a future caller, not a live defect.

equality**: `==` is true for a shallow copy too and would be exactly the vacuous guard F-144 is
about. Assert that the nested `excluded_terms` list inside the serialized dict **`is not`** the same
object as the live field's, and — better, because it tests the consequence rather than the
mechanism — that mutating the serialized structure leaves the scored leg unchanged.

Then add **R5 to that test's attack set** so the next reviewer inherits the mutation rather than
re-deriving it.

## Half 2 — the split-gate driver must abort on `errors > 0`

`docs/pwml_recovery_sprint/evidence/c102_goldreaders_split.py:65`:

```python
if proc.returncode not in (0, 1) or (proc.returncode == 1 and not counts["failed"] and not errors):
```

REV-102 attacked this two ways. On an unexpected exit code (planted bad import) it **fires**
correctly. On **the original F-114 condition** — a missing `--basetemp` parent — it **does not**,
because the guard was specified as *"nonzero exit with nothing failed and nothing errored"* and in
that scenario errors ARE present, so the second disjunct is false.

**The guard is faithful to its specification. The specification is what is incomplete.** D-083 rules
it: *"A run that loses 402 tests to setup errors still exits 0. The error counting makes the loss
visible but not fatal. **A setup error is never a legitimate outcome of this gate.**"*

### What to change

Make `errors > 0` abort on its own, independent of exit code and of `failed`. A setup error is an
**infrastructure failure**, in the same class as a surviving process — not a test result. The
existing `INFRASTRUCTURE FAILURE` message is the right channel; extend it to name the error count
and the file, so the log says which file lost its tests rather than only that something did.

Do **not** weaken the existing conditions while you are in there. The planted-bad-import case must
keep firing.

### Mandatory proof

Two positive cases and one negative, each recorded:

1. **Fires on setup errors:** point the driver at a selection with a missing `--basetemp` parent (the
   real F-114 condition) or otherwise induce collection errors, and show it now aborts where the
   committed log shows it did not. `evidence/c102_goldreaders_split_r1.attempt1-missing-basetemp-parent.log`
   is the committed record of the original behaviour — use it as your before.
2. **Still fires on an unexpected exit code:** the planted-bad-import case must not regress.
3. **Does not fire on a clean run:** the committed split log shows `errors=0` on every file. A normal
   green run must still complete. **This is the preservation case and it is not optional** — a guard
   that aborts a healthy run is worse than the gap it closes.
