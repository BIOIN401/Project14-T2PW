## 2. The defect, measured

`_rewrite_reaction_protein_enzymes_to_complexes` wraps a bare reaction enzyme in a generated
one-protein `protein_complex` because the PathWhiz importer refuses a bare protein as an enzyme.
That wrapper is a **technical representation of one protein**, not a biological claim about an
assembly. It is marked `generated: true`, `generation_reason: "single_protein_pathwhiz_wrapper"`.

**Then a later stage re-resolves it by name and gives it somebody else's identity.**

### Guard the ROW, not the branch — this is where a plausible fix fails

The component overwrite has **three** assignment branches, not one:

```python
9251  if result.get("status") == "mapped":
9257      complex_row["components"] = result["components"]          # <- the one you will notice
9258  elif _safe_list(complex_row.get("components")):
9259      complex_row["components"] = _reconcile_components_against_local_proteins(...)
9263  elif _safe_list(result.get("components")):
9264      complex_row["components"] = result["components"]          # <- writes the SAME superset list
```

**A guard placed on the `status == "mapped"` branch alone leaves the third branch able to write the
same four superset components** whenever the result carries components without status `mapped`. The
fix would look complete, pass a naive test, and not be.

**Therefore: guard the row, not the branch.** Decide once, before these branches, whether this
`complex_row` is permitted to take this `result`'s identity at all — and make that decision govern
the component write, the `pathbank_complex_id` write and the `pathbank_protein_complex_id` write
together. The `:9204` `if is_unknown_fallback_complex:` short-circuit already in this loop is the
shape to follow: a row-level decision taken before the resolution result is consumed.

**Your non-vacuity proof must exercise the third branch**, not only the first. If it does not, you
have proved half the guard.

Inside `PathBankDbResolver.map_complex_row`, the rule that matches is
**`resolved_component_species`** (`map_ids.py:2478-2521`): it takes the wrapper's single component's
`pathbank_protein_id`, calls `_find_complexes_by_component_protein_id`, and because
`len(component_candidates) == 1` it accepts the single candidate as `matched` **without any check
that the candidate's membership matches the wrapper's**.

## 5. Required direction — binding

* A generated single-protein wrapper **must not inherit the database identity of a multi-component
  superset complex**.
* **Exact biological complex mappings must continue to work.** When a complex row genuinely
  corresponds to the database complex — its membership matches — the mapping stands.
* A one-protein technical wrapper **may retain the protein identity** without pretending to be the
  larger biological assembly.
* **Do not globally disable component-to-complex resolution.** A *declared* complex row (not a
  generated wrapper) that lists partial components may still legitimately be enriched to the full
  database complex — that is correct grounding, not this defect. The distinguishing property is
  `generated: true` / `generation_reason: "single_protein_pathwhiz_wrapper"`: a generated wrapper is
  a technical artifact of the PathWhiz importer, not a biological claim. **Key your guard on that,
  not on component counts alone.**
* **Distinguish a pathway assembly from the specific catalyst assigned to one reaction.**
* **Do not inject unrelated catalysts into the reaction.**
* **Do not retain a database complex id when wrapper membership does not match that complex.** If
  the id goes, the id must go from `pathbank_complex_id`, `pathbank_protein_complex_id` and their
  `mapping_meta` mirrors — not from one and not the others.
* If no exact complex identity is justified, fall back to **the existing safe technical-wrapper
  representation** without a false database complex identity. Do not invent a new row shape.
* Act at the seam where the identity is **assigned**, not by scrubbing it afterwards. A post-freeze
  or exporter-side repair is an automatic reject under G8.
