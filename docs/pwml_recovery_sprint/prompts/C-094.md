## 2. The defect, measured — not inferred

PathBank ships a sentinel protein record for unidentifiable proteins: **`Unknown`,
`pathbank_protein_id = 9659`, `uniprot = "Unknown"`**. That record's own species in PathBank is
**`Arabidopsis thaliana`, `species_id = 4`, `taxonomy_id = 3702`**.

When every normal identity strategy fails, `_apply_pathbank_unknown_enzyme_fallback` and
`_apply_pathbank_unknown_complex_fallback` build a **generated wrapper complex** around that
sentinel so the named biological actor is preserved rather than dropped. **That preservation is
correct and you must not remove it.**

The defect is what the wrapper is then told it *is*. Three sites copy the **sentinel record's own
species** onto the **wrapper**:

| Site (base `14121d5`) | Function | Write |
|---|---|---|
| `map_ids.py:7354-7357` | `_apply_pathbank_unknown_enzyme_fallback` (enzyme actor) | `complex_row.update({... "species": _PATHBANK_UNKNOWN_SPECIES_NAME, "organism": ..., "species_id": 4, "pathbank_species_id": 4 ...})` |
| `map_ids.py:7587-7590` | `_apply_pathbank_unknown_enzyme_fallback` (transporter actor) | same `update()` |
| `map_ids.py:7921-7924` | `_apply_pathbank_unknown_complex_fallback` | same fields via `setdefault` |

`_PATHBANK_UNKNOWN_SPECIES_NAME = "Arabidopsis thaliana"` and `_PATHBANK_UNKNOWN_SPECIES_ID = 4`
(`map_ids.py:6802-6803`).

### Measured consequence

On the *Escherichia coli* paper `PMC12096016/strict`, committed at
`runs_verify/2026-08-27_1341/papers/PMC12096016/strict/final_mapped.json`:

```
enterobactin synthase complex   species = organism = "Arabidopsis thaliana"   Unknown-backed
porcine lactate dehydrogenase   species = organism = "Arabidopsis thaliana"   Unknown-backed
every other protein_complex     species = "Escherichia coli"                  not Unknown-backed
```

**Arabidopsis thaliana is a plant. Nothing in this paper is a plant.** Every Unknown-backed wrapper
gets Arabidopsis; every non-Unknown-backed one gets *E. coli*.

### The sharpest evidence — the `update()` clobbers a species that was already resolved correctly

The `enterobactin synthase complex` row is **internally contradictory**, and this is the part to fix:

```
"species":            "Arabidopsis thaliana"      <-- from the sentinel
"organism":           "Arabidopsis thaliana"      <-- from the sentinel
"species_id":         4                           <-- from the sentinel
"pathbank_species_id": 4                          <-- from the sentinel
"taxonomy_id":        "562"                       <-- E. coli, SURVIVED
"species_name":       "Escherichia coli"          <-- E. coli, SURVIVED
"species_ref":        {name: "Escherichia coli", species_id: 3, ...  status "matched", confidence 1.0}
"mapping_meta.species_resolution": {name: "Escherichia coli", species_id: 3, status "matched"}
"mapping_meta.cross_species_placeholder": true
"mapping_meta.target_organism": "Escherichia coli"
```

A correct, `status: "matched"`, `confidence: 1.0` species resolution **was already on the row**, and
`complex_row.update({...})` overwrote the four published fields with the sentinel's while leaving
`taxonomy_id`, `species_name`, `species_ref` and `species_resolution` behind. The code already
records `cross_species_placeholder: true` and `target_organism: "Escherichia coli"` — **it knows it
is holding a cross-species placeholder and publishes the placeholder's organism as fact anyway.**

The second aggravating fact: one of the two rows is `porcine lactate dehydrogenase`, a
**gold-forbidden identity** on this case (the coupled-assay reporter). A forbidden entity is handed
both a wrapper and a confident foreign organism.

Third: the Stage-3 gate reported these complexes as *missing species/organism* at
`post_normalization`, while the final payload carries Arabidopsis. **Species is being attached after
the gate that checks for it.** See § 5.

## 3. Required direction — binding

* An `Unknown` placeholder **must not contribute an unrelated real organism or species** to the
  entity it stands in for.
* **Do NOT default the entity to the requested organism.** That launders an unknown into a confident
  answer and is the F-127 failure mode in a new place. It is an automatic reject.
* **Do NOT default it to the dominant organism in the pathway.** Same reason.
* Missing identity evidence **must not become a confident organism assignment**.
* If species remains unresolved, **preserve that uncertainty explicitly** — an issue, an
  `identity_status`/lineage marker, and a `review_required` signal that already exists in this file.
  `not_evaluated` / `unavailable` is never `false` (`PRODUCT_CONTRACT` § 8).
* **Nothing may be silently lost.** The sentinel's own species is a real fact about record 9659.
  Keep it where it belongs — namespaced under `mapping_meta`, clearly labelled as the *placeholder
  record's* species, never as the entity's.

### The shape of the fix — stop *adding*, do not start *inferring*

An independent check of the same artifact confirmed everything above and raised one thing that
changes how you should frame this. The `enterobactin synthase complex` row already carries a
**separately resolved** species — `species_ref` / `mapping_meta.species_resolution`, *Escherichia
coli*, `species_id 3`, `status: "matched"`, `confidence: 1.0` — which the fallback's `update()`
overwrote. So the minimal correct fix is **not** "compute a better species". It is:

> **The Unknown fallback stops writing a species onto the wrapper at all.**

The wrapper is then left carrying whatever the normal species-resolution machinery already put
there — *E. coli* where that resolved, and **nothing** where it did not. That is *not* defaulting to
the requested organism and *not* defaulting to the dominant pathway organism, because the card adds
no inference of its own: it only stops clobbering. Prefer this to any rule that selects a
replacement value.

**One trap, and it is the reason this paragraph exists.** On the measured row,
`species_ref.source == "single_pathway_species"` — a *pathway-level* inference ("everything in this
pathway is one organism, so this is too"). That is precisely the dominant-organism reasoning § 3
forbids. It is pre-existing behaviour from an earlier stage and is **outside this card's boundary**:
leave it exactly as you find it. But **do not build on it** — do not read `species_ref`, or
`species_resolution`, or `taxonomy_id`, and copy it into `species`/`organism` as this card's
"replacement value". Promoting a pathway-level guess into a confident published organism is the same
laundering as defaulting to the requested organism, just sourced differently, and it is an automatic
reject. Removing the write is in scope; choosing a new value is not.
* Act at **the earliest coherent production seam** — the wrapper construction itself, not a later
  scrub. An exporter-side or post-freeze repair is a reject under G8.
