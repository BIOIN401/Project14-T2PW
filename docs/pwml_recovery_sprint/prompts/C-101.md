## 2. The defect

`placeholder_backed_proteins` counts **one number over two populations that get opposite answers**.
D-070 rules them apart; the instrument still conflates them, so no report can distinguish a PathBank
sentinel row from a generated functional wrapper, and the 24/82 withheld-identity population has no
metric of its own at all.

The census already half-knows this — `census["pathbank_unknown_sentinel"]` exists — but it is
computed on a **separate pass** from `placeholder_backed`, with no relationship enforced between
them, so a row can be counted in both and nothing notices.

## 3. Required categories — mutually exclusive, exhaustive, and none silently zero

Report these as **distinct counts**:

1. **PathBank `Unknown` sentinel rows** — `is_pathbank_unknown_protein(row)`.
2. **generated functional wrappers** — `generated: true` + `single_protein_pathwhiz_wrapper`; use
   `entity_identity.is_generated_complex_wrapper` rather than re-deriving the test.
3. **candidate identities correctly withheld** — F-141's confirmed-correct population.
4. **candidate identities lost despite sufficient support** — F-141's recoverable population.

**No row may count in more than one.** Assign each row to exactly one category and prove it with a
test that constructs a row satisfying two shapes at once and asserts it lands in one.

### The invariant, stated honestly

`placeholder_backed_proteins` **keeps its current value and meaning** — do not change what it counts.
Add the split beside it and assert:

```
placeholder_backed_proteins == sentinel_rows + generated_wrappers + other_placeholder_rows
```

**Report `other_placeholder_rows`; do not assume it is zero.** On the pinned run it is 0 and the
partition is exactly 16/5 — that is a *measured fact about that run*, not a structural guarantee, and
an instrument that asserts the invariant by dropping the remainder will hide the first row that does
not fit. This is the difference between a partition and an assumption.

### Category 4 is 0, and 0 is a measurement

F-141's classification measured **0** rows in category 4, pinned and corpus-wide: all 24 pinned
withheld rows are contractually correct withholding, because `identity_verdict.organism` is non-empty
on every one of them and the `species` rung's `unknown` can therefore only have come from the
candidate side. Your category-4 counter must be able to report a **non-zero** value when one occurs —
a counter hard-wired to 0, or one that cannot be exercised by a test, is vacuous. Write a test that
constructs such a row and asserts the counter moves.

**`0` here means "measured zero", never "not evaluated".** Follow `PRODUCT_CONTRACT` § 8's
`not_evaluated`-is-never-`false` rule and make the two distinguishable in the emitted report.
