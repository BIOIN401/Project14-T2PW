### Mechanism A — `PMC11487621` (*B. subtilis*, coenzyme A, 11 reactions)

`final_stage3_gate_report.json` is **clean** (`errors: []`). The **sole** export blocker is
`pwml_required_field_gate_report.json`, 2 errors, both on `/entities/species/1`:

```
species_missing_taxonomy        'B. subtilis'
species_missing_classification  'B. subtilis'
```

Three species rows for one organism:

| # | name at mapping time | name shipped | taxonomy | how |
|---|---|---|---|---|
| 0 | `Bacillus subtilis 168` | `Bacillus subtilis` | `1423` | NCBI backfill |
| 1 | `B. subtilis` | `B. subtilis` | **none** | unresolved at `species_hydration` — **this blocks** |
| 2 | `Bacillus subtilis (strain 168)` | **`Bacillus subtilis (strain`** | `224308` | PathBank sp. 100 via `gap_resolver_llm` |

**Row 2's malformed name is produced by our own code**, not by the LLM. Measured:

```
_deterministic_species_name("Bacillus subtilis (strain 168)")  -> "Bacillus subtilis (strain"
_deterministic_species_name("Escherichia coli (strain K-12)")  -> "Escherichia coli (strain"
_deterministic_species_name("Bacillus subtilis 168")           -> "Bacillus subtilis"       (correct)
_deterministic_species_name("Herbaspirillum huttiense subsp. huttiense IAM 15032")
                                                               -> "Herbaspirillum huttiense" (correct)
```

Why: the rank-marker test at `ir.py` compares `tokens[idx].casefold().rstrip(".")` against
`_STRAIN_RANK_MARKERS`, so `"(strain"` never matches because of the leading bracket; then the
trailing strain-code stripper eats `"168)"` and stops on `"(strain"`, which is neither a digit
token nor an all-caps code. The dangling open bracket survives. **A general defect in the whole
`(strain …)` family, not a one-off.**

`exact_symbol_identity` rescue requires `_normalize_name("PSAT") == _normalize_name("PSAT1")`,
which is `"psat" != "psat1"`.

Consequence: `no_candidate_passed_identity_verification` →
`all_normal_protein_identity_strategies_failed` → `pathbank_unknown_protein_fallback` →
the row's name and uniprot both become the literal string `Unknown`.

> **State this honestly in your report and do not overstate it.** No fallback overwrote an

> reordering or weakening the fallback.

## 3. What to implement

### A1 — `_deterministic_species_name`, `src/t2pw/pwml/ir.py`

Make the strain truncation bracket-aware so it can never emit an unbalanced fragment.

* Strip surrounding bracket punctuation from a token before testing it against
  `_STRAIN_RANK_MARKERS`, so `"(strain"` is recognised as the rank marker `strain`.
* After the cut is computed, drop any trailing token that would leave an unbalanced bracket.
* Keep the existing floor: never cut below genus + epithet.

Required outcomes:

```
"Bacillus subtilis (strain 168)"   -> "Bacillus subtilis"
"Escherichia coli (strain K-12)"   -> "Escherichia coli"
"Bacillus subtilis (strain"        -> "Bacillus subtilis"
```

Every currently-correct input must be unchanged, including
`"Herbaspirillum huttiense subsp. huttiense IAM 15032" -> "Herbaspirillum huttiense"` and
`"Bacillus subtilis 168" -> "Bacillus subtilis"`.

### A2 — contextual alias reuse in `backfill_species_taxonomy`, `src/t2pw/mapping/map_ids.py`

Add **one new deterministic pass**, applied **only** to species rows that the existing loop
leaves without both a `taxonomy_id` and a valid `classification`. It must be **inert on every
row that already resolves** — that is the property the reviewer will check first.

The rule, fail-closed at every step:

1. **Abbreviation shape.** The unresolved row's name must be a *single-letter* abbreviated
   binomial: one letter, an optional `.`, whitespace, then a lowercase epithet
   (e.g. `B. subtilis`, `E. coli`). Anything else — a multi-letter prefix, no epithet, a bare
   genus — is **not** eligible. Never expand an arbitrary abbreviation.
2. **Donors.** Species rows in the *same payload* carrying a valid `taxonomy_id` **and** a
   `classification` in `_SPECIES_CLASSIFICATIONS`, whose name yields a `Genus epithet`
   binomial via the existing `_binomial_from_organism`, with a genus longer than one letter.
3. **Compatibility.** Donor genus initial equals the abbreviation's initial (case-insensitive)
   **and** donor epithet equals the abbreviation's epithet (case-insensitive).
4. **Unambiguous expansion.** The compatible donors must agree on exactly **one** normalized
   binomial. Two different genera (`B. subtilis` with both *Bacillus* and *Brevibacillus*
   resolved in the payload) → **leave unresolved**. No compatible donor → **leave unresolved**.
5. **Tier 1 — offline reuse.** If the compatible donors carry exactly one distinct
   `taxonomy_id`, reuse that `taxonomy_id` and its `classification`. Fully deterministic, no
   network.
6. **Tier 2 — lookup repair.** If the compatible donors agree on the binomial but disagree on
   `taxonomy_id` (the `PMC11487621` case: `1423` species-rank vs `224308` strain-rank), the
   abbreviation is a **species-rank** reference and we may not pick between strains. Resolve
   the *expanded binomial* through the **existing** `_ncbi_taxonomy_lookup`, only when
   `enable_ncbi` is set and a client is available. If it returns nothing → **leave
   unresolved**. Invent no taxonomy and copy no strain-rank id onto an unqualified name.
7. **Display text is preserved.** Do not rewrite `row["name"]`. Normalization is for
   *lookup and identity* only.
8. **Record what happened** in `row["mapping_meta"]["taxonomy_backfill"]` with
   `source` = `"pathway_alias_reuse"` (tier 1) or `"pathway_alias_expansion_ncbi"` (tier 2),
   plus `expanded_from`, `expanded_to` and the donor names. Add a counter/list to the returned
   report so a run can be audited.

The existing NCBI attempt on the raw name stays exactly as it is and runs first, so nothing
that resolves today changes.

### B — gene-symbol-family rescue in `_name_gate_verdict`, `src/t2pw/mapping/map_ids.py`

Add **one** new rescue beside the existing `exact_symbol_identity` rescue. Do not change any
other rung, threshold or ordering.

* Applies **only** when `kind == "protein"`.
* Compare `_normalize_name(entity_name)` against `_normalize_name(symbol)` for each symbol in
  `_candidate_symbol_names(candidate)`.
* Keep **only** when one of the two normalized strings is the other plus a **trailing run of
  digits**, the shorter one ends in a letter, and the shorter stem is at least 3 characters.
  So `PSAT` ↔ `PSAT1` keeps; `PSAT1` ↔ `PSAT2` does **not** (neither is a prefix of the
  other); `A` ↔ `A1` does **not** (stem too short).
* Additionally require organism agreement using the existing `_uniprot_organism_matches` when
  both the request and the candidate name an organism — the same guard the alias rescue uses.
* Set `gate["verdict"] = "keep"`, `gate["reason"] = "gene_symbol_family_identity"`,
  `gate["matched_symbol"] = symbol`.

**Do not** touch `_names_share_meaningful_token`, `_name_gate_tokens`, `_candidate_display_names`,
`_candidate_symbol_names`, the score rung, the margin rung, the species rung, or
`_resolve_ambiguous_protein_candidates`.

Multiplicity is already fail-closed downstream: if this rescue lets two candidates with
different accessions verify, `_resolve_ambiguous_protein_candidates` returns
`multiple_candidates_passed_identity_verification` and nothing ships. Do not add a second
multiplicity rule.
