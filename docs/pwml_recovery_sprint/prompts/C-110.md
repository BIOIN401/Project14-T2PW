## 1. The ruling you are implementing

A case designated by gold as `context_only` **or an equivalent negative control** must **pass its
semantic expectation** when all three hold:

1. the pipeline releases **no pathway reactions**;
2. it provides the **required rejection or empty-pathway reason**;
3. the empty result is **not** caused by a timeout, crash, missing artifact, or infrastructure
   failure.

Report it under an explicit status — **`PASS_NEGATIVE_CONTROL`**, or the existing schema's closest
explicit equivalent if one already fits better. It must **not** be scored as a normal positive
pathway requiring reaction production.

**Binding, and each one is a merge gate:**

- **preserve the raw outcome** and **preserve the rejection reason** — the adjusted view never
  overwrites the raw one;
- **do not manufacture PWML**;
- **do not reward an empty result caused by execution failure** — this is the one that makes the card
  hard, see § 3;
- **do not change the official T-107 verdict** — see § 5, which is a hard prohibition;
- **test positive controls, true negative controls, timeouts, missing artifacts, and accidental empty
  outputs SEPARATELY.** Five populations, five tests, not one parameterised blur.

### Why this is worth a card at all

The instrument currently scores a **contract-correct empty pathway** as `RESULT: FAIL`. On
`PMC13231680/strict` the pipeline did exactly what the gold demands —

> `export_rationale`: *"the correct pipeline outcome is an empty pathway plus a rejection reason"*
> `notes`: *"this case exists to test whether the pipeline declines to produce output rather than
> inventing it"*

— and was marked failed for it. **T-105's PASS on that leg was the false positive**: it exported
`NDM-1`, `LpxC`, `Zn2+`, `PSA` and one reaction with zero lipid-A content, including two of the
case's own `forbidden_identifiers`. The trajectory is **T-104 correct → T-105 defective → T-107
correct again**, and **the instrument scored the defective run higher than either correct one.**

That is the defect. **The prohibition on writing code to recreate T-105's output currently lives in a
paragraph in a triage document nobody is required to read. It should live in the instrument.**

## 3. The hard part — condition 3, and it is the whole card

**An empty result must be rewarded only when it is a DECISION, never when it is a CASUALTY.**

Getting this wrong in the permissive direction is worse than not doing the card at all: it would
convert every timeout on a negative control into a `PASS`, and the sprint would lose the ability to
see a crashed leg on exactly the papers where "nothing" looks normal.

**F-148 is the standing evidence that this is not hypothetical:** a timed-out leg *preserves the stop
reason and little else*, and the current record cannot exclude retry amplification because the
killed run destroyed the evidence. **Read `F148-TIMEOUT-CLASSIFICATION.md` before you design this.**

So:

- **Enumerate what the leg actually carries** that can separate declined from killed — `failure_kind`
  (`no_reactions` on the good case), `boundary`, `issue_codes`, `research_failure`, `attempted`,
  `extracted`, payload presence. **Report what you found, including what is NOT available**, because
  the gaps are themselves a finding and they belong to F-148.
- **Default to FAIL when you cannot tell.** An indeterminate empty result is not a pass. Say so in
  the code and pin it with a test.
- Condition 2 — *"provides the required rejection or empty-pathway reason"* — is a **positive
  requirement**. A leg that produced nothing and said nothing is not a decline; it is a silence.

## 5. T-107 is IMMUTABLE — this is a hard prohibition, not a preference

**You may not re-score T-107's artifacts with the new instrument.** Not to validate it, not to show
the improvement, not "just to see". T-107 has run, been scored and been triaged; its verdict is
**`NOT ACCEPTED`** and **a run's verdict is a fact about the artifacts it produced.**

**Validate on FIXTURES you construct**, covering the five populations separately:

1. a **positive control** — a normal case that must still require reaction production;
2. a **true negative control** — empty, with a stated reason, no infrastructure failure → the new status;
3. a **timeout** → must **not** earn the new status;
4. a **missing artifact** → must **not** earn the new status;
5. an **accidental empty output** — empty with no stated reason → must **not** earn the new status.

**A test that cannot fail is not a test.** For each of the three that must NOT earn the status,
prove it fails to earn it.
