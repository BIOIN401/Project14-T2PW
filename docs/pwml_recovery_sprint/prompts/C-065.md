## 1. The hazard, measured at the base SHA

`tests/test_c011_freeze_seam_golden_equivalence.py` (449 lines) carries per-card helpers that **state** a
baseline move rather than absorbing it into the fixture:

| Helper | Address | Reversible? |
|---|---|---|
| `_with_c030_hash_keys` | `:237` | — |
| `_with_c052_path_keys` | `:281` | **yes** — `_without_c052_path_keys` at `:399` |
| `_with_c057_lineage_hashes` | `:353` | **NO. Structurally impossible.** |

**Why the third is different:** C-052's keys are **additive**, so an inverse can strip them and recover the
original exactly. **C-057's helper REPLACES a digest** — `canonical_payload_sha256`, and the `payload_sha256`
inside `final_stage3_gate_report` that records the same value again. **The pre-move digest is stored nowhere
else in the fixture**, so no `_without_c057_*` is expressible. That is a property of a replaced value, not an
omission by C-057.

**The trigger, at `:448-449`:**

```python
if __name__ == "__main__":  # regeneration, documented in the module docstring
    FIXTURE.write_bytes(_serialize(_without_c052_path_keys(_document(BASE_SHA))))
```

`_without_c052_path_keys` strips C-052's additive keys, so `__main__` cannot silently move the fixture by
*that* delta. **There is no equivalent protection for C-057's**, and `_document(BASE_SHA)` now carries the
lineage hashes — the file says so itself at `:338-339`.

**Consequence:** running that block turns a *stated* baseline move into a *silent* one. The golden is named
as a **BEFORE** document; once regenerated with the lineage hashes folded in, **it stops being one, and every
earlier card's stated delta becomes unverifiable at the same stroke** — because the document those deltas are
stated against no longer exists.

**Why HIGH although nothing is broken today:** the trigger is a **routine, sanctioned action**. Someone
regenerating for an unrelated legitimate reason destroys three cards' evidence as a side effect, **and the
suite goes green, so nothing reports it.** A latent trap whose trigger looks like maintenance is worse than
a red test.

## 4. Required behaviour

F-076 lists three candidate remedies and names the first strongest, because *"a comment stops a careful
reader; it does not stop a regeneration run in a hurry"*:

**Make `__main__` REFUSE to regenerate while any one-way helper is registered, requiring an explicit override
flag.**

Implement that. Design requirements:

1. **A registry of one-way deltas**, so the guard is data-driven rather than a hard-coded `if C-057`. The
   next card that adds a replacing helper must be able to register it in one obvious place — and, better,
   should find it hard *not* to.
2. **Refusal is the default.** Bare `python tests/test_c011_freeze_seam_golden_equivalence.py` must exit
   **non-zero**, write **nothing**, and explain: which one-way delta stands, why no inverse is expressible,
   and what the consequence of overriding is.
3. **An explicit override flag** permits regeneration for a genuine future product decision. Make it
   awkward and self-documenting — a bare `--force` is too easy. The message it prints must say what is being
   destroyed.
4. **The reversible C-052 path must keep working exactly as today** when no one-way delta is registered.
   Do not break the mechanism that already works.
5. `test_the_fixture_regenerates_byte_identically_from_the_base_blob` (`:435`) and the equivalence assertions
   at `:418-419` and `:441-445` **must keep passing unchanged.** They are the reason the file exists.
