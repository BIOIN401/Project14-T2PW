## 2. Step 1 — the cheap offline probe, because you cannot instrument a path you cannot see

F-148 § 3 leaves **three readings** open, all consistent with `elapsed = 1800.4` and **none excluded
by the artifacts**:

1. the child **never honoured** its 1680 s deadline;
2. the child **did** stop near 1680 s and its **finalization itself exceeded** the 120 s reserve;
3. the reserve is real but **nothing on the outer-kill path invokes finalization at all**.

**Which one is true determines what there is to instrument**, so separate them first.

F-148 already specifies the probe: **short, cheap and OFFLINE — a synthetic child that overruns,
driven against `pipeline/deadline.py` and the runner's child-launch seam
(`resolve_leg_timeout`, `child_deadline_seconds`, `DEFAULT_FINALIZATION_RESERVE_SECONDS`,
`runner.child_command`). NO LLM spend, NO benchmark leg, NO T-run, NO rerun of any T-107 leg.**

**Write the hypothesis for each of the three readings BEFORE you run the probe**, and record what
each would look like if true. Then measure.

One recorded hint, and F-148 is explicit that it is a hint and not a measurement:
`PMC12444477/strict` fired an **in-process** `operation_timeout` at **1798.3 s**, not at 1680 s,
which suggests the in-process deadline is keyed to something other than the child deadline the
parent computed. **Treat it as a lead to test, never as a conclusion to confirm.**

## 3. Step 2 — what the instrumentation must preserve

A leg that is killed, times out, or crashes must leave behind, durably, on the path that survives
cleanup:

1. **attempt count by stage**;
2. **retry reason** (per retry, where one occurred);
3. **per-stage elapsed time**;
4. **finalization-reserve consumption** — how much of the reserve was available, used, and left;
5. **timeout source** — which mechanism fired: in-process deadline, outer parent kill, wrapper, or
   provider. **These are genuinely different and the run currently reports two of them as one.**
6. **whether a payload existed before cleanup**;
7. **cleanup decisions affecting partial artifacts** — what was discarded, and by which decision;
8. **total model calls**, where available;
9. **terminal state before wrapper cleanup**.

### Two things about `stage=unknown` you must not "fix"

`stage=unknown` on the outer-kill path is **not a defect. It is honest** — the parent genuinely does
not know, because it killed a child that never reported back. The in-process path knows it was at
`stage=input` and declares its missing budget rather than guessing, which is **F-092 defect 3 closed
and the one thing here working as the contract asks**.

**Do not make the parent guess a stage.** Add a comment so no future reader mistakes `unknown` for a
pipeline stage, and make the *timeout source* explicit so the two epistemic situations are
distinguishable — that is item 5, and it is the honest fix.

## 4. Security — a hard boundary on what you may record

**Observability must not expose secrets, prompt contents beyond existing policy, or user
credentials.**

- **Record attempt COUNTS, reasons, timings and hashes — not prompt bodies.** PRODUCT_CONTRACT § 9
  speaks of *"attempt numbers, prompts/models and response hashes"*; **stay within existing policy on
  prompt content and do not widen it in this card.** If you believe § 9 requires more than current
  policy permits, **report the conflict — do not resolve it yourself.**
- **Reuse the existing secret-scanning patterns** rather than writing new ones:
  `evidence/g11/g11_evidence.py` already carries detectors for OpenAI-style keys, GitHub tokens,
  Google API keys, AWS access key ids, bearer tokens and inline secret assignments.
- Anything written to a durable artifact must pass that scan. **Prove it does, with a test that
  plants a fake secret and shows it is caught** — a scanner nobody has seen fail is not a scanner.
