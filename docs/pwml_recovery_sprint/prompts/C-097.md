## 2. The defect

C-089 unified two readers onto one participant-key list. Its charter scoped the legacy `ref`/`id`
tail to `identity_admission`. But **both** readers consume `PARTICIPANT_NAME_KEYS`, so
`bench.semantic._names` began treating `ref` and `id` as entity-name keys, **which it never did**.

`participant_schema.py` already carries the correct split, and its own comments already say why:

```python
PARTICIPANT_SCHEMA_NAME_KEYS = ("name", "entity", "compound", "protein",
                                "protein_complex", "element",
                                "element_collection", "nucleic_acid")

#: Keys ``identity_admission`` has always carried that appear in NO model. Kept
#: as an additive tail, never promoted into the union above: a reader that stops
#: seeing them can only start stripping identities.
PARTICIPANT_LEGACY_NAME_KEYS = ("ref", "id")

PARTICIPANT_NAME_KEYS = PARTICIPANT_SCHEMA_NAME_KEYS + PARTICIPANT_LEGACY_NAME_KEYS
```

`ref` and `id` **appear in no participant model**. They exist for `identity_admission`, where losing
them would start stripping identities. `bench.semantic._names` has the opposite need: it wants
entity *names*, and an `id` is not one.

## 3. The fix — and the whole reason this card is small

`src/t2pw/bench/semantic.py:235`:

```python
keys = _schema().PARTICIPANT_NAME_KEYS          # <- reads the union, including ref/id
```

becomes a read of **`PARTICIPANT_SCHEMA_NAME_KEYS`**.

**Do not create a new tuple, a new constant, a local list, or a filtered copy.** The canonical
definition already expresses exactly this distinction; the card is to consume the right half of it.
If you find yourself writing a key list, you have taken a wrong turn — stop and report.

`identity_admission` keeps consuming the full `PARTICIPANT_NAME_KEYS`, unchanged. That is the
preservation obligation and it is the one that matters: **a reader that stops seeing `ref`/`id` can
only start stripping identities**, so `identity_admission` must not narrow.

Update the `_names` docstring, which currently explains the C-089 unification and will otherwise
describe behaviour the code no longer has.
