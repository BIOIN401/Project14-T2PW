## 3. Root cause

`map_payload` (`src/t2pw/mapping/map_ids.py:8068-8079`) resolves each entity row against
external databases in three independent per-row loops (proteins `:8159`, complexes `~:8600`,
compounds `:8684`). It has:

- **no access to the source paper.** Its signature takes no text.
  `map_ids.py:7719-7722` states this as policy: *"Stage 2 resolves names against databases
  and never reads the paper"*, and stamps `paper_explicit = "not_evaluated"`.
- **no cross-row accession index.** Nothing prevents two rows claiming one accession.

The accession-collision rule already exists twice, but only in `bench/`
(`semantic.py:908-919`, `semantic_production.py:250-259`) and only **after** the strict
quarantine — by which time the accession is already inside `final_mapped.json`.

## 4. Required change

### 4a. Make the source reachable — without touching `streamlit_app.py`

`entity_admission.screen_additions`
(`src/t2pw/pipeline/entity_admission.py:406`) **already receives `seed_text`** on the real
batch path (`streamlit_app.py:5554`, `:5674` pass it) and already mutates the payload (it
writes `entity_admission_report`).

Have it additionally write a compact, versioned **source index** onto the payload — a
normalized (casefolded, punctuation-squashed) copy of the seed plus its length and a schema
version. This changes **no call signature anywhere** and needs no edit to `streamlit_app.py`.

⚠ **Verify empirically that this actually reaches `map_payload` on both the strict and the
research batch leg**, and report how you verified it. If it does not, stop and report — do
not work around it by editing `streamlit_app.py`.

### 4b. Withhold unsupported identities — in `map_payload`

At the tail of `map_payload`, beside `_record_mapping_lineage` (`map_ids.py:7935`), consult
the index. A row about to ship real external accessions must have **at least one** of its
name, `raw_name`, `aliases`, `short_name` or `synonyms` locatable in the index, compared
punctuation- and case-insensitively.

If none is:

- **withhold the accessions — do not delete the entity.** Move them to `rejected_mapped_ids`
  with a distinct reason (e.g. `identity_not_supported_by_source`), exactly as the existing
  name gate does via `_strip_rejected_identifiers` (`map_ids.py:5377`) and
  `_NAME_GATE_ISSUE` (`:4459`). Merge rule 7 binds: preserve incomplete-but-correct work,
  never drop it.
- record the refusal in the mapping report and in `provenance_lineage`
  (`_mapping_lineage_facts`, `map_ids.py:7775`) so the decision is auditable.

**Fail open.** If the index is absent (unit tests, the `interactive_curator` path at
`curation/interactive_curator.py:570`, legacy payloads), the gate must not fire. An absent
index is "not evaluated", never "unsupported". Mirror `entity_admission.py:53-56`.

### 4c. Refuse duplicate accession claims — in `map_payload`

After all three mapping loops, build a `(namespace, accession) → {normalized entity name}`
index. Where one accession is claimed by more than one **differently-named** entity, the
claim is incompatible and must not ship. Withhold rather than delete, as in 4b, with its own
reason. Be deterministic about which claimant keeps it (or withhold from all) — state your
rule in the report and test it.

This must run **before** the canonical freeze, inside mapping. Merge rule 8 binds: exporters
must not repair biology after the graph is frozen, and the card explicitly forbids "merely
deleting identifiers after export".
