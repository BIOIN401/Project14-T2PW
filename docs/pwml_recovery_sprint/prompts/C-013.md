## CARRIED TO C-030 — binding, added post-merge

Authority: `CONTROL-PLANE-RECONCILE-001` §7. Source: the C-013 merge record `09fb40d`,
finding 3. C-013 is merged; this section adds no work to C-013 and changes no shipped
behaviour. It is a **precondition on C-030**, which already depends on C-013.

**The contradiction, resolved in favour of identity completeness.** The merge record
states it exactly:

> **ALLOWLIST GAP, LIVE.** `mapping_meta` / `candidates` are excluded by `C-013.md:49`,
> while `src/t2pw/pwml/ir.py:74-91` uses them as the exporter's identifier fallback
> feeding `_db_id` -> `record["pathwhiz_id"]` at `:416` and `:444`. The reviewer measured
> the reachability: **60 committed rows** carry a PathWhiz identifier ONLY under
> `mapping_meta`/`candidates`, so an edit confined there changes exported entity identity
> while `canonical_graph_sha256` stays byte-identical (confirmed empirically). … `C-013.md:49`'s
> "EXCLUDE … mapping_meta, candidates" and the ACCEPTANCE line "every biological dimension
> in `PRODUCT_CONTRACT` §5 moves the graph hash" cannot both hold for those 60 rows.

**Ruling.** `PRODUCT_CONTRACT` §5 outranks the card's EXCLUDE list. The exported entity
identity is biology; a hash that does not move when it moves is asserting a false
guarantee. C-013's EXCLUDE line is qualified above so it cannot be cited the other way.

**C-030 REQUIREMENTS — all binding, all acceptance-testable.**

1. `canonical_graph_sha256` **must include** the normalized identifier fallback values
   reached through `mapping_meta` and `candidates` **when, and only when, those values are
   actually consumed to establish canonical entity identity** — i.e. the values that reach
   `_db_id` -> `record["pathwhiz_id"]` (`ir.py:74-91`, `:416`, `:444`).
2. It **must not** hash candidate **ranking order**, scores, transient metadata, retry or
   lookup bookkeeping, or provenance noise carried in the same containers. Widening the
   allowlist to the whole of `mapping_meta`/`candidates` is a **failure**, not compliance:
   the allowlist must stay an allowlist and must still satisfy C-013 test (f).
3. **Acceptance must cover the 60 committed rows** the merge record measured as dependent
   on that fallback. Enumerate them from the committed `final_mapped.json` corpus, and pin
   the count so a silent change in reachability is loud.
4. **Acceptance must prove the hash moves**: changing an identity-relevant fallback value
   **changes** `canonical_graph_sha256`. Assert the paired negative too — changing a
   ranking-only or provenance-only field in the same containers leaves
   `canonical_graph_sha256` byte-identical while `canonical_payload_sha256` moves. One
   direction alone does not prove the split (the same standard C-013 test (a) applies).
5. C-013's other three carried preconditions are unchanged and still due at C-030: the
   latent `synonyms`/`aliases` gap (`ir.py:1149`), the latent `moldb_inchi`/`moldb_inchikey`
   gap (`ir.py:394-395`), and the `canonical_payload_sha256` **name collision** with the
   schema-1 key written at **`streamlit_app.py:3659`** and pinned at
