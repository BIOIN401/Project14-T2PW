# C-076 — a shared accession within one kind is identity, not conflict (scorer + gold)

**Card type:** measurement correction — scorer and gold classification. **No pipeline change.**
**Finding:** F-102 · **Ruling:** product owner, 2026-08-23.
**Base SHA:** to be set at dispatch (integration tip at the time).
**Branch:** `agent/c076-alias-holo-apo-identity`

---

## 1. The ruling this card implements, verbatim

> The same UniProt accession may be shared by proven aliases of the same protein and by holo/apo
> states of the same underlying polypeptide. `EntE` and `enterobactin synthase` are the same protein
> identity. Holo-EntB and apo-EntB may share the underlying UniProt accession while remaining
> distinct pathway states. **Do not flag these as accession conflicts unless the entities are
> biologically unrelated or cross-kind. Update the scorer/gold classification rather than forcing
> the pipeline to invent different protein identities.**

## 2. What is wrong today, measured at T-105

Every surviving `accession_claimed_by_multiple_entities` finding in
`runs_verify/2026-08-22_2147` is **within-kind**:

```
uniprot:P0ADI4   <- EntB / holo-EntB              (both entities.proteins)
uniprot:P10378   <- EntE / enterobactin synthase  (both entities.proteins)
```

`bench/semantic.py:908-919` flags any accession answering to two differently-**named** rows.
`no_real_id_or_name_conflict` is a **gating** semantic check (`release_status.py:101`), so these
demote real legs.

**This is the exact predicate C-073 was rejected for using in the pipeline**, on the grounds that
it contradicts **D-035 clause 3c** (a matching stable external identifier is *proof* two
differently-named rows are the same entity). Measured then: over 53 artifacts the name-difference
rule stripped 92 claimant-incidences across 36 rows, 41 of 42 pairs legitimate. The pipeline was
corrected to a cross-kind rule. **The scorer was not, and now embodies the rejected rule.**

Separately, `holo-EntB` carrying `uniprot:P0ADI4` is scored as a **false real identifier**
(`forbidden_kind: strain_or_construct`), which is one of T-105's seven priority-1 rows.

## 3. The gold entry, and the distinction that resolves it

`src/t2pw/bench/gold/pinned_v1.json`, PMC12096016 `forbidden_identifiers`:

```json
{"name": "apo-EntB", "aliases": ["holo-EntB", "apo-Fur", "holo-Fur", "R196A"],
 "kind": "strain_or_construct",
 "reason": "Modification states and a site-directed mutant; all collapse to the parent protein."}
```

The gold's own reason — *"all collapse to the parent protein"* — **agrees with the ruling**. Its
concern is the pipeline inventing a *separate protein identity*, which the ruling also forbids.
The entry over-reaches only in that it makes a holo/apo state sharing the parent accession count as
a fabricated identity.

**The entry mixes two different biological cases and only one of them is a modification state:**

| alias | what it is | under the ruling |
|---|---|---|
| `apo-EntB`, `holo-EntB` | the same polypeptide with/without its phosphopantetheine arm | **may share the parent accession** |
| `apo-Fur`, `holo-Fur` | the same polypeptide with/without bound Fe²⁺ | **may share the parent accession** |
| `R196A` | a **site-directed mutant** — a different polypeptide sequence | **stays forbidden** |

That distinction is the whole card. Do not collapse it.

## 4. Required change

### Arm A — the scorer

`bench/semantic.py` `_check_id_conflicts`: a `(namespace, accession)` answering to more than one
differently-named row is a conflict **only when the claimants are biologically unrelated or of
incompatible kind**. Within one kind, treat it as D-035 clause 3c agreement and do not emit a
finding.

- The pipeline already has the kind notion — `identity_admission.entity_kind_class`
  (protein-ish = `proteins` + `protein_complexes`; compound-ish = `compounds`). **Reuse it; do not
  write a second definition that can drift.** `bench/semantic.py` already imports from
  `t2pw.pipeline.entity_identity` at `:852`, so a function-local import is the established grain.
- Keep emitting the finding for cross-kind claims. `drugbank:DB00114` on `ALAS2` (protein) vs
  `Pyridoxal 5'-phosphate` (compound) must still be a conflict — that is the one true defect
  C-073 fixed in the pipeline and the scorer must agree with it.
- `_check_id_conflicts` returns `(CheckResult, false_real)`. **The collision branch must continue
  not to increment `false_real`** (`semantic.py:908-919` currently appends without incrementing) —
  do not change that coupling as a side effect.

### Arm B — the gold

Split the entry so `R196A` keeps its `strain_or_construct` classification while the four
modification states no longer make a shared parent accession a fabricated identity. Update the
`reason` text so it states the new rule rather than the old one.

- **Do not delete evidence.** A modification state emitted as a *standalone protein row with its
  own invented accession* is still wrong; only *sharing the parent's* accession becomes legitimate.
  If the gold schema cannot express that distinction, say so in your report and propose the
  minimal schema addition rather than deleting the entry.
- Touch **only** this entry. Every other `forbidden_identifiers` row in the gold stays byte-identical.
