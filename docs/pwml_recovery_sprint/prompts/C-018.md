### Requirement 1 — a `participant` verdict never protects an entity

**A `participant` verdict must NEVER protect an entity from hallucination removal, and
must never be read as evidence that the entity is paper-supported.** The merge record
proves the verdict cannot carry that information:

> A full `forbidden_identifiers` sweep across all ten gold cases returns EXACTLY ONE
> `participant` verdict: `succinyl-CoA` / PMC12180156 -> participant/high. That entry is a
> gold HALLUCINATION TEST ("zero occurrences in the entire 67,304-character file, body and
> references alike"). The SAME molecule under PMC12856317, where the paper does quote "the
> condensation of glycine and succinyl-CoA", returns the IDENTICAL participant/high. Two
> opposite ground truths, one identical verdict, separated only by paper support — which
> `classify_entity` cannot accept as input. **C-060's hallucination gate must run BEFORE
> and INDEPENDENTLY of any `cofactor_policy` consultation.**

**Enforceable form.** C-060's acceptance must pin, against
`src/t2pw/bench/gold/pinned_v1.json`: (a) the hallucination gate runs before and
independently of any `cofactor_policy` call — provable by ordering, not by comment;
(b) `succinyl-CoA` / PMC12180156 is **removed** even though it classifies
`participant/high`; (c) `succinyl-CoA` / PMC12856317 is **retained**; (d) the two are
separated by paper support and by nothing else. A rule keyed on `hub` or
`cofactor_or_currency` without an evidence check is likewise forbidden (merge-record item
2), and the module's `reason` must never be emitted as the audit-trail justification for a
removal (item 3).

### Requirement 2 — the R-003 harness must read the gold objects correctly and fail closed

The merge record records the method hazard the auditor caught in its own first pass:

> gold `expected_substrates`/`expected_products` entries are OBJECTS `{name, quote}`, not
> strings. Feeding the raw object to `classify_entity` returns a uniform `unknown/low` for
> all 50 and **READS AS A PERFECT ALL-CLEAR**. The harness must extract `name` and
> `aliases` or it will silently certify nothing.

**Enforceable form.** The R-003 harness must:

1. **extract `name` and `aliases`** from every gold object it evaluates — never pass the
   raw `{name, quote}` mapping to `classify_entity`;
2. **fail closed** if the intended cohort size or the intended assertion count is **zero**.
   A run that evaluates nothing must terminate as an error, never report a clean sweep. Pin
   the expected non-zero cohort and assertion counts against
   `src/t2pw/bench/gold/pinned_v1.json` so a shape change in the gold file is loud;
3. be demonstrated non-vacuous: a deliberately mis-extracted cohort (raw objects, or an
   empty selector) must make the harness **fail**, not pass.
