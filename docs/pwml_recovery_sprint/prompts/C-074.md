### F-100 — coverage scored against the paper instead of the request

`runs_verify/2026-08-22_2147`, `PMC13231680/strict` — the declared **negative control**:

```
release  : release_ready       artifact: pathway.pwml
coverage : requested_core_declared=True  coverage_ratio=1.0  unmatched_terms=[]
           requested_core_source=pathway_context
           pathway_name=""                       <-- EMPTY
           key_compounds=["phthalylsulfacetamide (PSA)","meropenem (MEM)","Zn2+","sulfacetamide"]
           key_proteins =["NDM-1 (...)","LpxC (...)"]

```

The batch requested **lipid A biosynthesis in E. coli**. The context carries **no pathway name at
all**, and its key terms are the paper's own subject matter. Coverage then scored 6/6 against
terms derived from the paper, so `completeness` came back `1.0` and the gate passed.

Gold `export_rationale`: *"Nothing lipid-A-related is exportable at any level of partiality. The
correct pipeline outcome is an empty pathway plus a rejection reason."*

This is the mechanism `collect_requested_core_terms` explicitly warns about
(`strict_quarantine.py:770-777`): *"Never derived from the surviving graph. Terms taken from what
survived would match whatever survived, which is not a test."* The terms here are not literally
taken from the surviving graph, but they are taken from a Stage-0 reading **of the same paper**,
which defeats the check the same way.

## 2. Root cause — measured, do not re-derive

`evaluate_core_coverage` (`strict_quarantine.py:839-962`) enforces
`thresholds = {'min_core_processes': 1, 'min_core_coverage': 0.5}`.
`min_core_processes` counts **accepted processes including interactions** — 3 and 5 on the two legs
above — so a floor of 1 is trivially cleared by a payload with a single real reaction.

The **chemically connected** core is computed in production already —
`semantic_production.py:468`, `report.graph = _s._connected_core(processes, _s._cofactor_names())` —
and `_check_connected_core(graph, minimum)` at `:278` returns
`_not_evaluated(CHECK_CONNECTED_CORE, NO_CORE_FLOOR)` whenever `minimum` is `None`. No caller
passes a floor, so the check never evaluates.

`CHECK_CONNECTED_CORE` is additionally listed as deliberately **non-gating**
(`release_status.py:88`) on the stated grounds that it *"duplicates a floor the coverage verdict
already enforced at this same seam"*. **That justification is false as measured:** the coverage
floor counts processes-including-interactions at a threshold of 1; the connected-core floor counts
chemically connected reactions. On both legs above they disagree, 3-vs-1 and 5-vs-1.

## 3. Required change — two arms, one seam

### Arm A — a real connected-pathway floor for `release_ready`

`release_ready` must require a **largest chemically connected core of at least 2 reactions**,
unless a one-reaction pathway is **explicitly the requested scope**. Below the floor the status
becomes `review_required` — never `diagnostic_only`, never dropped (merge rule 7).

- Reuse the connected-core computation that already exists; do not write a second one. The
  function-local `t2pw.bench` import from `t2pw.pipeline` is established precedent at
  `strict_quarantine.py:2341` and `:2355` and is asserted function-local by
  `tests/test_semantic_release_gating.py:450`. Keep it function-local.
- "Explicitly the requested scope" means the request itself states a single-reaction pathway.
  Derive it from the request, never from what survived, and never from a paper identifier.
- **Do not hardcode any benchmark paper, PMC id, pathway name or gold value into production.**
  That is an automatic reject.

### Arm B — an unstated request is not a satisfied request

When the requested pathway is not actually stated — an empty or blank `pathway_name` with no
explicit `requested_core` argument — coverage must not report a satisfied verdict that permits
`release_ready`. "Nothing was asked for" is currently read as "nothing is missing"; it must read as
**not judgeable**.

- Prefer surfacing this as coverage being unevaluable rather than as a fabricated failure. The
  existing vocabulary already has `REASON_COVERAGE_NOT_EVALUATED`
  (`release_status.py:111`) and `CoverageVerdict.completeness` already returns `None` in the
  undeclared regime (`release_status.py:188`) — follow that grain.
- An explicit `requested_core` argument passed by a caller still counts as a stated request.
- This must not turn every context-free unit-test payload into a failure. Undeclared-core
  behaviour that exists today must be preserved; the new refusal is specifically about a context
  that *claims* to declare a core while stating no pathway.

### Both arms are subtractive

They may only ever remove `release_ready`. Neither may create one, and neither may promote or
demote past `review_required`.
