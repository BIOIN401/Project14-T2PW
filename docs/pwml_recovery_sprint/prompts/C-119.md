## 1. The defect, in one sentence

A leg whose **final, live** gates all pass is destroyed — no PWML at all — because
`batch/driver.py::_blocking_reports` counts errors from a report the app itself stamps
`phase: audit_round` and documents as *"not a verdict about what shipped"*
(`streamlit_app.py:4055-4060`).

Measured: **4 of the 6 evaluable strict legs of the unseen pilot.** Their shipped payloads pass
the production predicates with 0 objections, and the failing reports cite
`/entities/proteins/5`, `/13`, `/15` against shipped protein lists of length **2, 3, 8** —
pointers the shipped payload cannot host.

**The goal is NOT to weaken any biological gate.** It is to stop treating superseded
intermediate audit state as a reason to destroy an otherwise serializable final pathway.

## 2. The change — EXACTLY three seams, nothing else

### Seam 1 — `src/t2pw/batch/driver.py::_blocking_reports` (lines 1026–1056)

Make the blocking scan phase-aware.

1. **Exclude only reports explicitly stamped `phase: audit_round`.** Any other phase — or a
   report with no phase at all — keeps today's behaviour exactly.
2. **Fail closed when no authoritative later boundary exists.** If nothing in the artifact set
   supersedes the `audit_round` snapshot — no `post_audit_contract_report`, no
   `post_remap_contract_report`, no final stage-3 gate report — the snapshot **is** the latest
   verdict available and it MUST still block. *Absence of a final boundary is never success.*
3. **Preserve historical behaviour for pre-phase-stamp artifacts.** An artifact set whose
   contract reports carry no `phase` key at all predates the stamp; it keeps the old
   arithmetic unchanged so archived runs keep their recorded verdicts.

**The precedent is in this same file, 70 lines below, at `:2506-2521`.** The *gate* channel had
this identical defect and was fixed by routing it through
`t2pw.pipeline.gate_reports.gate_verdict`, which *"reads the final report and nothing else,
fails closed on every uncertainty, and falls back to the old arithmetic only for artifact sets
stamped as pre-change."* **Read that function and follow its three properties.** You are
bringing the contract channel into line with a decision already made and reviewed for the gate
channel.

### Seam 2 — batch finalization in `src/t2pw/batch/driver.py` (around `:2583`)

Where **F0–F4 all pass** and the *only* remaining blocker is superseded intermediate state:

1. **serialize the final canonical pathway** rather than calling `_finalize_gate_failure`;
2. the disposition **must be `review_required`** — never `release_ready`;
3. **the superseded-report condition must survive as an explicit review reason** in the
   release record and the manifest row. It must be readable by a human afterwards: what was
   superseded, at which phase, how many errors. **A superseded error silently disappearing
   from review metadata is a reject.**

F0–F4 are defined in `ORCH-728` § 1 and are already computed at this seam or immediately
around it: mode serialises · canonical payload exists · final live stage-3 gate passes · final
semantic contract passes **with F-179 included** · connected core ≥ `MIN_CONNECTED_CORE_REACTIONS`.

### Seam 3 — `src/t2pw/pipeline/release_status.py::classify_release_status`

Add a **sixth cap** with exactly the shape of the five that already exist (semantic,
incomplete-core, connected-pathway, unstated-request, pre-freeze):

1. it may move **only** `release_ready → review_required`;
2. **exactly one step** — never to `diagnostic_only`;
3. it may **never create** `release_ready`, and never touch a status the chain already lowered;
4. its new parameter **defaults to `None` / not-recorded**, so every existing caller stays
   byte-identical.

Read the five existing caps and their comment blocks before writing it. They explain why the
shape is what it is, and the fifth (`prefreeze_review_required`, `C-087`/`D-068`) is the closest
model.
