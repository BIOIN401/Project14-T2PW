## Why the verdict must not grow, in one paragraph

`test_c074_strict_core_floor.py:462` compares a demoted leg's coverage record against the same
payload under a different request, excluding **only** `requested_context` — the field that *is* the
designated request echo. C-114's `subprocess_coverage` is derived from
`requested_context.main_subprocesses`, so it put **request-derived content into the verdict outside
the one key set aside for it**. That is a change in what the document *means*. The test noticed, and
it was right to. **This card keeps the meaning by keeping the bytes.**

## LEAD RULING — 2026-09-02, on C-116's three disclosures

**All three were disclosed unprompted and none is a substantive defect. One needs correcting, one is
accepted with a follow-up, one is accepted outright.**

### 1. The G11 sequence reuse — **MUST BE CORRECTED, and a budget is granted for it**

Six pytest jobs first ran through bare `-m pytest` rather than `pinned_pytest.py`, making them
**measurement-unverified** under `TEST_MATRIX` § 0 rule 10 — correctly identified, and correctly
excluded from the record as test results. They were re-run properly and only the pinned versions
committed.

**But the retries took sequences 03–08 with `-pinned` labels while the superseded attempts were moved
out of the tree.** `evidence/g11/README.md` is explicit:

> *"Sequences are never reused, so a **re-run cannot overwrite the attempt it replaces**. An
> infrastructure failure stays on the record. (`H-004/02-smoke.json` is a real example: **a
> mis-invoked smoke run, kept**; `03-smoke.json` is the retry.)"*

**The `H-004` precedent is exactly this case and it points the other way.** The mis-invoked run is
**kept at its sequence**; the retry takes the next one. Here the record shows only the retries, and
six real jobs — which produced **valid cleanup certifications with zero survivors**, and whose only
defect was measurement-tree verification — have vanished from a directory whose stated purpose is
that *"a G11 claim must be checkable against a committed artifact."*

**RULING: commit the six superseded reports at NEW sequences `09`–`14`**, labelled to mark them
superseded, so the record shows both the attempt and its replacement. **Machine-evidence budget
revised to ≤ 22 artifacts and ≤ 60 KB** to accommodate them — the implementer was right that
committing them under the old ceiling was not its to authorize.

**The implementer's handling was otherwise exactly right:** it caught its own rule-10 violation,
declined to report unpinned runs as results, re-ran correctly, and flagged the budget consequence
rather than either hiding the supersession or silently exceeding the ceiling.

### 2. The four-name artifact map — **ACCEPTED, with the gap recorded and a follow-up registered**

The diagnostics document **is** a fifth entry in `payloads`, so it is written by the same function, in
the same loop, and archived by the same block. **The ruling's requirement is met: "verdict written,
diagnostics absent" is unreachable.**

The returned `{name: path}` map deliberately keeps **four** names, because two unowned tests assert it
by equality (`test_batch_driver_quarantine_artifacts.py:112`,
`test_streamlit_quarantine_boundary.py:595`) and `batch/driver.py:1489` iterates a hard-coded
four-name tuple. **Adding a fifth key would have broken two detectors and required edits to three
unowned files — an automatic reject under merge rule 2.** Excluding it was the correct call.

**The consequence is real and is recorded rather than glossed:** the document lands on disk beside
`coverage_summary.json` in the leg directory — which is where every probe, census and audit in this
sprint reads from, so the D-088 clause 7 purpose is served — but **it is not carried across the
batch/Streamlit artifact seam.** **Registered as R-C116-1**, a follow-up card owning those three
files. Not chartered now: this wave is finishing, not widening.

### 3. `clear_quarantine_artifacts` — **ACCEPTED, registered as R-C116-2**

`:2755` deletes only the four original filenames, so a stale `coverage_diagnostics.json` can outlive a
run that dies before the boundary. **Real, small, and correctly left alone as unowned.** It belongs on
the same follow-up card as R-C116-1.

### 4. The seam choice — **ratified, and the reasoning is better than the alternative I implied**

An instance attribute on `CoverageVerdict` (a `dict` subclass with no `__slots__`) is invisible to
`json.dumps`, `dict()` and `==`, and survives `deepcopy`. **A second return value was rejected on
evidence, not taste:** `evaluate_core_coverage` has four call sites outside the ownership boundary, so
a tuple return would have forced edits to unowned files. **The card offered both and the implementer
chose the one that keeps the boundary; that is the right reading.**

**The risk it names against itself is the reviewer's first target:** the attribute's lifetime. Any
future caller doing `dict(coverage)` loses it, and the fallback emits `diagnostics_computed: false`
with `unmatched_terms` still copied verbatim rather than inventing rows. **Whether that is the right
failure mode rather than raising is a judgement for `REV-116`.**
