## CARRIED TO C-056a — binding, added post-merge

Authority: `CONTROL-PLANE-RECONCILE-001` §7. Source: the C-017 merge record `fc8b059`,

### 1. Organism comparison must NOT be wired as-is

The merge record measures the defect:

> **ORGANISM COMPARISON HAS NO SYNONYM RESOLUTION.** `semantic_production.py:125-140`
> compares with `normalize_name` equality/prefix only. Measured: requested `"E. coli"` vs
> observed `"Escherichia coli"` -> `organism_compatible ok=False`,
> `cross_organism_reactions=1`. Same for `"Homo sapiens"`/`"human"` and
> `"S. cerevisiae"`/`"Saccharomyces cerevisiae"`. … MUST be resolved before C-056a merges
> `organism_compatible` into `release_status`.

**C-056a REQUIREMENTS — binding.**

1. **C-056a must not wire the current literal organism comparison unchanged.** Wiring
   `organism_compatible` into `release_status` while it still compares literals is a
   **failure of C-056a's acceptance**, not a deferrable finding: it would refuse correct
   pathways for a spelling.
2. Organism comparison **must reuse the repository's established synonym /
   canonicalization behaviour**, including the pinned case **`E. coli` ≡ `Escherichia coli`**.
   The audited implementation already exists at `rag/eligibility.py:1366-1404` —
   `_organism_aliases`, `_canonical_organism` and `_taxon` (which also drops strain
   suffixes, so `Escherichia coli K-12 MG1655` matches its species). Prefer reuse of
   those, **or** of the single shared owner selected under **D-016**.
3. **Do not create a competing synonym table.** A second organism vocabulary is a TRAP-4
   rebuild and would drift silently from the audited one — the same failure mode C-018's
   merge record already documents for the two cofactor vocabularies. `rag/eligibility.py`
   is `MASTER_PLAN` §2 read-only material (`:147`) owned by no card: reuse it by import,
   do not edit it, and escalate if an edit is genuinely required.
4. **Acceptance must cover all six axes, each asserted:**
   - **positive** — `E. coli` ≡ `Escherichia coli`; `S. cerevisiae` ≡ `Saccharomyces cerevisiae`;
     `Homo sapiens` ≡ `human`; a strain-qualified name ≡ its species;
   - **negative** — genuinely different organisms still compare **incompatible**, and the
     bare genus alone (`Escherichia`) does **not** stand in for the binomial;
   - **abbreviation** — `E. coli`, `E.coli`, `E coli` all resolve alike;
   - **whitespace** — leading/trailing/repeated internal spaces do not change the verdict;
   - **punctuation** — the period in `E.` and hyphens in strain suffixes do not change it;
   - **deterministic regression** — the same inputs give the same verdict across processes
     and repeat calls, with no ordering, hash-seed or clock dependence.
5. **A widened comparison must not become a licence to pass.** Assert the direction: the
   change may only convert a **false incompatible** into **compatible**; it may never
   convert a genuine cross-organism reaction into a pass. Pin `cross_organism_reactions`
   on a real cross-organism case.

### 2. `confirmed` can never be True on a production run

Carried verbatim from the merge record:

> `confirmed` can never be True on a production run, because
> `retained_reactions_match_supported_signatures` requires quote-verified gold signatures
> and is always inapplicable. **C-056a must combine `evaluated` + `ok` +
> `inapplicable_checks`; gating on `confirmed` alone would ship nothing, ever.**

**Binding:** C-056a's release-status input **must** be computed from `evaluated`, `ok` and
`inapplicable_checks` together. Gating on `confirmed` alone is a defect, and acceptance
must include a test that fails if the gate is reachable only through `confirmed`.
A check carrying an `inapplicable_reason` has `ok is True` by construction and must not be
read as evidence that the question was asked and answered.
