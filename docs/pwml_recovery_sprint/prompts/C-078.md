## 2. What I measured

### 2a. The refusal record is never consulted at this seam

`grep -rn "rejected_mapped_ids" src/ --include=*.py` returns hits in `mapping/identity_admission.py`,
`mapping/map_ids.py` and `pipeline/entity_identity.py`. It returns **zero hits in
`src/t2pw/pwml/`** — the whole pre-freeze resolution package, including the function that decides
whether a DB match may stamp identity on a row.

### 2b. The mechanism, in current source

`compound_resolution.py:502` keys the legacy branch on the row still carrying a PathBank scalar:

```python
legacy_id = _db_id(row, ["pathbank_compound_id", "pw_compound_id", "pathwhiz_id"])
if legacy_id is not None:
    ...  # legacy_id_unverified, continue
```

When the identity gate withheld that scalar, `legacy_id` is `None`, the branch is skipped, and the
row falls through to `resolver.resolve(row)` — a **name-keyed** lookup against a live PathBank.
`_admit_db_identity` (`:382`) then decides admission from `chosen_rule`, `confidence` and
corroborating external ids. **It never reads the refusal record.**

### 2c. What admission actually does — F-099's own scope note is WRONG here

F-099 states: *"Not affected: `mapped_ids`. hmdb / kegg / chebi / pubchem / cas / biocyc /
chemspider stay withheld… Affected: the strict PWML export path only."*

`db_resolver.py:459-472`, the admitted branch of `apply_compound_db_resolution`:

```python
out["pathwhiz_id"]  = chosen.get("id")
out["pathbank_compound_id"] = chosen.get("id")
out["pw_compound_id"] = chosen.get("id")
out["hmdb_id"]      = chosen.get("hmdb_id")
```

`mapped_ids` is **rebuilt from the DB row**, not merged and not filtered. Every namespace the
identity gate withheld comes back if the matched PathBank record carries it. Those namespaces are
exactly what acceptance **priority 1** counts.

And this runs **pre-freeze**, so the restored identity enters the canonical graph. This is not an
exporter repairing biology after the freeze (merge rule 8) — it is worse: the refused identity
becomes canonical.

## 4. Required change

A DB match may not stamp an identity that this row's own `mapping_meta.rejected_mapped_ids` already
refused. On refusal the match is **record-only**.

**Reuse the machinery that already exists.** `apply_compound_db_resolution(..., admit_identity=False)`
already does exactly the right thing: the row keeps its extracted name, gains no identifier, and the
refusal is recorded (`db_resolver.py:441-456`, D-028 rule 3 — one flag and one early return, never a
partial apply). The call site at `compound_resolution.py:572` already passes it. **Do not build a
second refusal mechanism; make `_admit_db_identity` return the decision it should already be
returning.**

### Choosing the predicate

Recommended, and the shape F-099 itself proposes — **refuse when the matched DB row would restamp a
namespace that appears in this row's `rejected_mapped_ids`.** It expresses the actual rule ("a later
pass may not undo an earlier refusal") and it is precise rather than blunt.

Rejected alternatives, and why — do not implement these without arguing against my reasoning:

* *Any row with any non-empty `rejected_mapped_ids` gets no DB identity.* Too blunt. `Fe3+` has a
  `kegg` refusal and a legitimate legacy-branch resolution; this would strip unrelated rows.
* *Refuse only when the PathBank scalar itself was refused.* Under-reaches: the damage is
  `mapped_ids` being rebuilt, and a match can restore `chebi`/`kegg`/`pubchem` regardless of which
  scalar triggered the fall-through.

Derive the predicate yourself and defend it. If measurement says mine is wrong, say so.
