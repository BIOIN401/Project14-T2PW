## 1. The defect, in one sentence

`batch/driver.py::_superseded_contract_reports` excludes exactly one non-authoritative phase,
`audit_round`, so a `post_normalization_contract_report` stamped **`initial_post_normalization`**
— the *other* phase `gate_reports.py` documents as *"never a verdict about what shipped"* —
still fails a leg whose final gate, `post_audit`, `post_remap` and pre-export boundaries are all
clean.

Measured on **four papers across three independent cohorts**: `PMC13184244`, `PMC13089919`,
`PMC13123502`, `PMC4471609`. In each, that report is **the only failing report in the artifact
set**, and it validated the **pre-remap** payload — the one the Unknown-backed-complex policy has
since replaced.

**The goal is NOT to weaken any gate.** It is to stop a pre-Stage-3 snapshot from vetoing a
payload that the authoritative boundary has already judged.

## 2. Why this is subtractive, and why no abstraction needs building

**The authoritative final contract verdict already exists and already blocks export.**
`streamlit_app.py:4738`:

```python
stage3_gate_report, stage3_contract_report = _validate_stage8_export_payload(payload)
if not bool(stage3_contract_report.get("ok", False)):
    return {"ok": False, "error": "PWML export stopped by validation-only pre-export Stage 3

```

`_validate_stage8_export_payload` (`:4594`) runs **the same gate suite** and **the same
`validate_post_normalization`** on the exact payload about to serialize, fail-closed (`ok` must
be explicitly true). `pwml/ir.py:2619` enforces the same protein invariant a third time.

**Do not build a new `contract_verdict()` abstraction.** You are removing a redundant early veto
so the existing authoritative boundary is reached. Adding an abstraction that duplicates
`_validate_stage8_export_payload` is out of scope and will be rejected.

## 3. The change — ONE seam

### `src/t2pw/batch/driver.py::_superseded_contract_reports` (`:1193`)

This function is the **single** source for four downstream channels — the blocking exclusion
(`:1279`), the release-status cap (`:2018`), the review warning (`:1916`) and the PWML filename
(`:2067`). Widening its predicate makes all four follow. **Do not add a second path.**

Replace the single-phase test at `:1230`

```python
if _report_phase(report) != PHASE_AUDIT_ROUND:
    continue
```

with a predicate requiring **all** of the following. Conditions 1 and 2 already exist and must
be preserved unchanged.

1. `_artifact_set_is_phase_stamped(artifacts)` — legacy unstamped sets keep the old arithmetic.
2. `_superseding_boundaries(artifacts)` is non-empty — absence of a later boundary still blocks.
3. **`effect_on_failure == "feed_audit"`.** Set by exactly one contract,
   `validate_post_normalization` (`stage_contracts.py:219`); every other contract uses `"abort"`.
   The driver currently never reads this field at all. **Production states the report's role and
   the consumer ignores it.**
4. **`phase` is in a CLOSED set of explicitly non-authoritative phases** —
   `PHASE_INITIAL_POST_NORMALIZATION` and `PHASE_AUDIT_ROUND`, imported from `gate_reports`,
   never spelled as literals.

### Condition 4 must be an allow-list, NOT `!= PHASE_FINAL_PRE_EXPORT`

`_report_phase`'s own docstring states the doctrine: *"an unstamped report is a report whose
boundary this code cannot identify, and the safe reading of 'unidentified' is 'live'."* A
negated test would silently enrol any future or malformed phase string into the excluded set.
**Enumerate the two phases the module defines as non-authoritative and fail closed on everything
else.** The set is complete by construction — `gate_reports.py` defines exactly three phases —
not a list that grows.

### Two consequences you must also handle

* **The emitted descriptor hard-codes `"phase": PHASE_AUDIT_ROUND` (`:1240`).** It must report
  the report's **actual** phase, or the review metadata lies about which boundary was superseded.
* **The `C-119` release cap must fire on the new phase.** It is reached through the same
  descriptor list, so it should follow for free — **prove it does** rather than assuming.

### Optional, same-file only

`_finalize_gate_failure`'s message (`:2472`) names `verdict.stage` — the boundary that **passed**
— while the issues come from the stale boundary. *"post-pipeline validation failed: N blocking
issue(s) at `final_pre_export_stage3_gates`"* on a leg whose final gate is clean is what made an
earlier reading of these legs look like a final-gate failure. Fix it **only** if the fix stays
inside `_finalize_gate_failure`. If it does not, leave it and report it.
