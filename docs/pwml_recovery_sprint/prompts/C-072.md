## 4. Root cause — measured, do not re-derive

`evaluate_core_coverage` (`src/t2pw/pipeline/strict_quarantine.py:839-962`) sets

```python
960        "minimum_core_satisfied": not reasons,
```

where `reasons` has exactly three clauses (`:917`, `:930`, `:934`): nothing survived, core
process count below `min_core_processes` (1), coverage ratio below `min_core_coverage` (0.5).

`missing_anchors` is `unmatched_terms` — **recorded, never a predicate.** With coverage
0.8 ≥ 0.5, one surviving core process and a non-empty graph, `reasons == []`, so
`minimum_core_satisfied` is `True` while three requested anchors are unmatched.

`classify_release_status` (`src/t2pw/pipeline/release_status.py:431-577`) then falls through
its chain to `:515 status = RELEASE_READY`, and `:570` sets
`strict_acceptance_eligible = (status == RELEASE_READY)` → `True`.
`driver._pwml_artifact_name` (`src/t2pw/batch/driver.py:1474-1492`) reads that status and
returns the reserved bare name `pathway.pwml`.

## 5. Required change

**Add an independent demotion in `classify_release_status`:** when the requested core was
declared and one or more requested-core anchors matched no admitted process, `RELEASE_READY`
is not available; the status becomes `REVIEW_REQUIRED`.

Model it on the existing semantic cap at `release_status.py:547-552`:

- **one step only**, `release_ready → review_required`. It must **never** produce
  `diagnostic_only` and must never demote a status that is already `review_required` or
  `diagnostic_only`.
- append a distinct, greppable reason string (a new module constant in the style of
  `REASON_SEMANTIC_EVALUATION_FAILED`) naming the unmatched anchors.
- it must be **independent of** `semantic_evaluation`. With `semantic_evaluation == "passed"`
  and every structural gate green, a declared core with unmatched anchors must still yield
  `review_required`.

`strict_acceptance_eligible` then follows automatically from the `:570` invariant, and the
artifact name follows automatically from `driver._pwml_artifact_name`. **Do not touch either.**

### Why here and not in `evaluate_core_coverage`

Adding a fourth clause to `evaluate_core_coverage.reasons` would make the pinned
`min_core_coverage = 0.5` threshold non-load-bearing and would break the tests that pin it
(`tests/test_release_status_classification.py:301`,
`tests/test_strict_quarantine_release_seam.py:222`). Leave `evaluate_core_coverage`
untouched. `CoverageVerdict` already exposes `missing_anchors`
(`release_status.py:190-195`) and `requested_core_declared`, which is everything the new
predicate needs.
