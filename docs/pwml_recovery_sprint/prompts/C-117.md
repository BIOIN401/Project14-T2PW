## Why this is a card and not a chore

Three of these four sit on the **remediation path for a failure that has now recurred twice** (F-151,
then F-171). `test_c106`'s failure message tells the next agent to re-measure with
`orch717_census_probe.py`; that probe then prints reference values three re-pins out of date. **The
tool an agent is sent to for correct numbers hands it wrong ones.** That is not cosmetic — it is a
trap laid across the exact route the sprint's own instrumentation directs traffic down.

## LEAD RULING — 2026-09-02, on the two things C-117 escalated instead of deciding

**Both escalations were correct, and both are defects in THIS CARD, not in the work.**

### 1. The acceptance line contradicted the implement step. **The implement step governs.**

The card says two incompatible things about `orch717_census_probe.py`:

- IMPLEMENT R-C115-3: *"Prefer a form that CANNOT go stale again — e.g. print the live value and the
  pin it was compared against, **read from the source**"*, reinforced by TRAP-B;
- ACCEPTANCE: *"`git diff` contains ONLY comments and string literals."*

**Reading a pin out of the suite requires code.** The acceptance line was written for the other three
files and over-applied to the fourth; it makes the card's own headline instruction unsatisfiable.

**RULING: the probe's `import re`, its `pinned()` helper and its six `PIN_*` constants are RATIFIED
and in boundary.** Nothing added is an assertion, a threshold, a comparison or a number; the probe
still asserts nothing, and its measurement code is byte-identical. **The acceptance line is corrected
to: for `orch717_census_probe.py`, only the printed labels and whatever minimal read-only machinery
is required to source them live; for the other three files, comments and string literals only.**

**This is the better outcome and not merely the permitted one.** A hardcoded reminder that happens to
be right today is the thing that produced all four residuals. A label read from the assertion it
mirrors **cannot** desynchronise: a pin moved in the suite moves in the probe in the same commit, and
a renamed assertion prints `PIN NOT FOUND` instead of a wrong number. **The implementer also
converted P7, which was still correct**, on the same reasoning — that is the card's intent applied
rather than its letter.

### 2. The machine-evidence budget was one report short of the card's own required list

The card requires four runs (census, mutation attack, probe, SMOKE) and budgets **≤5** cleanup
reports. A pre-edit baseline for **both** the census files and the mutation attack needs **six**.

**The implementer spent the fifth slot on the census baseline — the files it actually edited — ran
the mutation attack once post-edit, and did NOT self-authorize a sixth.** That is exactly D-019: *"no
implementer, reviewer or test-runner may self-authorize one, and technical success or later approval
does not cure one."*

**RULING: accept the single post-edit mutation run.** Its reasoning is sound and checkable — the only
edit to that harness sits inside `if code != 0:`, which a green baseline never executes, so the sole
failure an A/B could have caught is import-time breakage, and the post-edit run printed
`BASELINE (unmutated tip) exit=0` plus `all 8 mutations detected`. **The pre-edit arm is assigned to
`REV-117`, which has its own budget.**

**This is the second card in a row whose machine-evidence budget was unsatisfiable as written** —
C-114's omitted the mandatory `.pin.json` verdicts, C-117's omitted a slot for the baselines its own
FOCUSED TESTS section implies. **Standing correction: a machine-evidence budget must be derived by
counting the card's required runs, doubling for any before/after arm, and adding the pin verdicts —
not estimated.**

  the card.
