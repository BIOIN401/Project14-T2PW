## 3. The design question you must answer, not just the numbers

**Do not simply change 38 to 60.** That buys a green suite until the next run directory is committed,
and this card exists because that already happened.

Decide, and justify from the record:

* Should the census be **derived** (count what is committed, assert a *property* of it) rather than
  **pinned** to a literal?
* If a literal is genuinely right — because the pin's purpose is to catch an *unexpected* corpus
  change — then what makes the next legitimate addition **not** a false red? A pin that must be
  hand-edited every time a run lands is the defect, not the number.
* Which property was C-074 actually protecting? Read its charter and merge commit. **Preserve that
  property.** If the literal count was incidental to it, say so; if it was load-bearing, say that
  instead and keep it with a maintenance path.

**A green test that no longer checks what C-074 wrote it to check is a worse outcome than the
current red.** State plainly which property survives your change.
