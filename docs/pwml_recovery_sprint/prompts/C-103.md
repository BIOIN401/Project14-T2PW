## 2. What is actually wrong — and it is not the code

Two tests fail, both parametrized `[only_unrelated_reactions_survive]`:

```
tests/test_strict_failure_replay.py::test_every_stored_strict_failure_replays_to_its_recorded_verdict
tests/test_strict_failure_replay.py::test_recovered_cases_are_smaller_and_refused_cases_are_not_claimed
```

**One root cause, two symptoms.** The fixture records `expect.recovers: false`;
`quarantine_and_close(...).ok` is now `True`.

**The coverage gate is entirely correct.** Measured:

```
coverage.core_accepted_processes      = 0
coverage.auxiliary_accepted_processes = 1
coverage.minimum_core_satisfied       = false
coverage.reasons = ["core_process_count_below_minimum:0<1",
                    "requested_core_coverage_below_minimum:0.000<0.500"]
```

**What moved is where that verdict goes.** C-041a (`4177fe5`, under D-002) deliberately routes a
`minimum_core:*` shortfall to `review_reasons` — instead of `refusal_reasons` — when a defensible
core survives. `ok` is `not refusal_reasons`, so **`ok` stopped answering the question the fixture
asks it.**

**The protection did not vanish. It moved, and it is richer:**

```
release.status                     = "review_required"
release.strict_acceptance_eligible = false
release.completeness               = 0.0
release.missing_anchors            = ["L-glutamate","glutathione","glutamate-cysteine ligase"]
release.expansion_blocked_reason   = "3 requested-core anchor(s) matched no admitted process: …"
```

The empty-graph sibling `every_reaction_unresolvable` **still hard-refuses** to `diagnostic_only`,
so the distinction C-041a drew is live and the control works.

**Merge rule 7** requires the current behaviour verbatim — *"preserves incomplete-but-correct
pathways as `review_required` rather than dropping them"* — and `has_surviving_core`'s docstring
anticipates this exact payload: *"A fragment that is merely shallow, or merely **not the pathway
that was requested**, is still a fragment; it becomes `review_required`, never `diagnostic_only`."*

**The fixture predates D-002 and measures a pre-D-002 seam. The code is right; the expectation is
stale.**

## 3. ⚠ THE TRAP — the obvious fix is wrong and would destroy the test

**Do not simply flip `expect.recovers` to `true`.**

Doing so makes `test_every_stored_strict_failure_replays_to_its_recorded_verdict` take its
`if expect["recovers"]:` branch, which asserts full strict validity of the reduced payload — and
**silently drops the `coverage_reason` assertion in the `else` branch.** The one test written to
stop an off-topic survivor from reading as a win becomes a rubber stamp.

Read the module docstring; it says why this case exists:

> *"What is never a correct result is a graph that passes because the pathway was emptied out or
> replaced by unrelated survivors — `every_reaction_unresolvable` and
> `only_unrelated_reactions_survive` exist to keep that from ever reading as a win."*

**That property must survive this card intact.** The corrected test must still go **red** if
`strict_acceptance_eligible` ever becomes `true`, or `release.status` becomes `release_ready`, for
this payload.

## 4. What to build

Re-point the expectation at the seam that now carries the verdict. The shape is yours to design, but
it must satisfy all of:

* the fixture expresses **what the run is classified as**, not merely whether `ok` is a Boolean —
  `release.status`, `strict_acceptance_eligible`, and the `review_reasons` prefix at minimum;
* **`recovers` keeps a defined meaning** for the other eight cases, all of which currently pass —
  do not repurpose the key underneath them;
* the **refusal cases still assert their `coverage_reason`**;
* `every_reaction_unresolvable` still asserts a **hard refusal** to `diagnostic_only`, and that
  assertion must be reachable — prove the two cases are distinguished, not merged;
* the module docstring is updated to describe the seam it now measures, and to name D-002/C-041a as
  the reason.

**Preferred shape:** add expectation keys rather than overloading `recovers`. A case that is
*refused* and a case that is *review_required with zero core coverage* are two different facts and
the fixture should be able to say both.
