## 1. The two defects

**G11 unmatched-selector false green.** `check --task <T>` resolved a nonexistent task to
`[]`, and `check_many([])` printed *"0 artifact(s), 0 non-compliant"* and exited **0**, so a
typo'd or renamed task ID certified a branch holding no evidence. An explicit path beside it
dropped `--task` entirely, concealing the miss. Fixed in `resolve_selection`; no
artifact-validation rule is weakened.

**Chunk D per-file isolation is insufficient, and per-node had never been tested.** Running
`qb` as one process holding all 23 `AppTest` objects *is* the documented cause
(`tests/test_streamlit_quarantine_boundary.py:425-430`), so that partition left the fault
intact. `run` now isolates per **node**. The verdict parser was also too permissive — it
summed `passed|failed|xfailed|xpassed` off the last matching line, so a skip, xfail, xpass
or deselection could read as coverage and a missing summary as zero.

### 2.1 Addendum — one aborted attempt, and the label prefixes actually used

**The declared order, count and content in §2 are unchanged.** Recorded here because an
attempt was made and must not vanish.

The first `base1` attempt was **aborted by the agent harness at its 10-minute foreground
limit** — not by the gate and not by `bounded_run.py`. A complete run costs ~10 min, so it
sat exactly on that limit. It is **not a gate verdict**: the outer wrapper was killed before
writing its `--json`, and under the D-1 precedent a run whose report was never written is
not evidence of record. Retained and disclosed: **31 written child reports**, sequences
15–45, labelled `base1-*`, all reading `completed` / `cleanup_success` / 0 survivors / exit
0 — the 4 collection jobs, the core, and 26 of 27 isolated nodes at base. Its two
*reserved-but-never-written* placeholders (`14`, `46`) were removed, since a reservation
holds no evidence and `check` correctly rejects one; `allocate` never reissues a sequence.
**Zero owned processes survived**, verified by process enumeration — the wrapper's
`KILL_ON_JOB_CLOSE` Job Object tore the tree down with it.

The six scheduled runs therefore execute under **`bounded_run.py` launched as a tracked
background job** — bounded waiting and guaranteed cleanup stay with the wrapper, and nothing
external kills it mid-run — under prefixes **`g1base` `g2base` `g3base` `g4cand` `g5cand`
`g6cand`**, distinct from the aborted attempt's.

**Classification, per the product-owner ruling:**

- stable 177/177 across all six → the per-node runner is the authoritative blocking gate;
- an isolated node that flakes at **both** base and candidate → test-infrastructure race:
  the deterministic 154 (150 core + 4 `s8`) stay blocking, the affected `qb` cohort becomes
  mandatory-to-run and mandatory-to-report but temporarily non-blocking, and the race is
  filed as a backlog item;
- candidate-only, newly deterministic, or diff-implicating → an actual blocker.

No production assertion is weakened, no failure is retried until green, no test is omitted,
and no reproducible regression is relabelled environmental.
