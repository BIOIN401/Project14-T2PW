PATHWAY-DIAGRAM SCOPING RULE

For pathway-diagram extraction, especially from large papers or review articles, prefer a constrained and human-readable pathway over an exhaustive biochemical inventory.

Your task is to identify the main pathway story and represent only the central biochemical backbone needed to understand it.

Default behavior for broad documents:
- Extract the core precursor -> intermediate(s) -> product pathway.
- Include only the most central reactions and explicitly relevant enzymes.
- Include major branch points only if they are central to the pathway narrative.
- Collapse or omit peripheral branches, derivative families, comparative examples, methods content, and general mechanistic discussion.
- Do not treat every biochemical mention in the paper as a required graph element.

If the user does not explicitly request exhaustive extraction, choose the smallest coherent pathway that best represents the paper's main pathway.

REACTION SCOPE AND COLLAPSED BRANCHES

- Extract full biochemical reactions only for the selected core pathway backbone.
- For downstream families or broad derivative classes, do not expand every reaction unless explicitly requested.
- Represent broad downstream branches only as visualization/subpathway summaries if the schema supports the specific summary cleanly; otherwise omit them from reaction extraction.
- Do not create reaction nodes for general statements such as "oxidation, methylation, and hydroxylation produce diverse derivatives" unless a specific substrate and product are given.
- If upstream context names excluded_examples, excluded branches, or collapsed material, keep that material out of entities, reactions, and modifiers unless the user explicitly asks for exhaustive extraction.

HARD OUTPUT RULES — the downstream pipeline enforces these;
violations cause hard failures or silent data loss
════════════════════════════════════════════════════════════

REACTIONS
• Every reaction MUST have ≥1 input AND ≥1 output. Omit the reaction if either side is empty.
• Every reaction MUST have a verbatim evidence quote (≤25 words) from the source text.
• Every entity name in inputs/outputs MUST exactly match a name declared in entities.

ENTITIES
• Every protein in entities.proteins[] MUST appear in at least one modifier. A protein with no
  process role fails a hard gate and kills the pipeline. Do not declare proteins you cannot connect.
• No composite entity names. "A + B" or "A and B" are not valid names — split into separate inputs/outputs.
• No empty placeholder objects. {"name": ""} must not appear anywhere.
• Deduplicate: each entity name must appear once within its registry list.

MODIFIERS
• modifiers[] accepts only proteins or protein_complexes. Compounds, cofactors, and ions
  are silently dropped at export — do not put them here.
• Valid roles: catalyst | transporter | activator | inhibitor
• Every named enzyme or catalyst in the text MUST appear in its reaction's modifiers[] with role "catalyst".
• If the text names a protein complex as the catalyst, use entity_type "protein_complex" in modifiers[].
  The complex's subunits go in protein_complexes[].components, NOT as separate modifiers.
- Speculative enzymes are not confirmed catalysts. If an enzyme is described as possible,
  predicted, candidate, unknown, a paralogue, or only a generic family, do not assign confidence
  1.0. Omit it unless the reaction is central and the source supports that specific enzyme-reaction
  link; when included, use lower confidence and inferred provenance.
- Do not create proteins for broad enzyme-family discussion unless the enzyme is attached to a
  specific selected pathway reaction.

COFACTORS — this rule supersedes everything above for small molecules
  PLP, pyridoxal phosphate, FAD, FMN, NAD+/NADH, NADP+/NADPH, SAM, CoA, ATP/ADP/AMP,
  GTP/GDP, heme, haem, TPP, thiamine pyrophosphate, biotin, lipoic acid, iron-sulfur cluster,
  Mg2+, Fe2+, Fe3+, Zn2+, Mn2+, Cu2+, and all similar biochemical helpers:
  → If stoichiometrically consumed/produced: place in inputs/outputs only
  → If present but not consumed: add to entities.compounds with class "cofactor", omit from reaction
  → NEVER place in modifiers[]

TRANSPORTS
• cargo must be a single entity name — never composite.
• from_biological_state and to_biological_state must reference declared biological_states by name.
• transporters[] may be empty when no carrier protein is named in the text.
• Create the transport even if the transporter is unknown — the movement itself is what matters.

BIOLOGICAL STATES
• Every biological_state must have both a species field AND a subcellular_location field.
• Set compartment_canonical to the matching value from the fixed vocabulary below.
• Species must be in binomial format (Genus species) or abbreviated binomial (G. species).

COMPARTMENT CANONICAL VOCABULARY (use exactly these values):
  cytosol | nucleus | mitochondrion | mitochondrial_matrix | endoplasmic_reticulum
  golgi | lysosome | peroxisome | plasma_membrane | extracellular | endosome

PROTEIN COMPLEXES
• Create protein_complex entries only when the text explicitly names a complex, holoenzyme,
  heterodimer, or multisubunit structure.
• Each component in protein_complexes[].components must be a protein that also exists
  in entities.proteins[].

VALID CLASS VALUES
════════════════════════════════════════════════════════════
compounds:          compound | cofactor | ion | element_collection
proteins:           protein | transporter
protein_complexes:  protein_complex
nucleic_acids:      nucleic_acid
reactions.class:    biochemical_reaction | transport_reaction | activation | inhibition | binding
interactions.class: activation | inhibition | binding | interaction
scope_membership:   core | anaplerotic | cataplerotic | auxiliary | out_of_scope
confidence:         1.0 for extracted, 0.0–1.0 for inferred
provenance:         extracted | enriched | inferred

Interaction endpoints must be real entities only. Never put process/event phrases
such as "X formation", "X activation", "Y conversion", "Z biosynthesis",
"A degradation", "transport", "reaction", "pathway", "cycle", or "process" in
entity_1/entity_2. If a protein catalyzes a process, model it as a reaction with
compound inputs/outputs and put the protein/protein_complex in modifiers[] with
role "catalyst"; use the process phrase only as the reaction name or evidence.
