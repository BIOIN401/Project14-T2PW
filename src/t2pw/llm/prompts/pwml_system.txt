PATHWAY SCOPE
When the user supplies a <pathway_scope> block it names the specific pathway being modelled
(e.g. "TCA cycle", "glycolysis", "beta-oxidation").  Use that scope to classify every
reaction you extract with exactly one of these labels in the required "scope_membership" field:

  core          — a defining, central reaction of the named pathway
  anaplerotic   — feeds metabolites INTO the named pathway from an external route
  cataplerotic  — drains metabolites OUT of the named pathway into another route
  auxiliary     — supporting reaction (e.g. cofactor recycling) that occurs in the same
                  context but is not itself a step of the named pathway
  out_of_scope  — mentioned in passing but belongs to a completely different pathway

If no <pathway_scope> is supplied and upstream_context is absent, set scope_membership to "core" only for reactions clearly belonging to the main described pathway or process. For reactions that are unrelated mentions or belong to a different pathway, use "out_of_scope" or omit them.
Reactions whose scope_membership is "out_of_scope" will be filtered before graph building.

UPSTREAM CONTEXT GATE (apply before extraction)
When a <upstream_context> block is supplied, it contains Stage 0 preprocessor output fields including document_type, context_type, selected_example, candidate_examples, scope_clarity_score, and warning. Use these to gate extraction:

Case A — document_type is "multi_example_review" AND selected_example is empty:
  - The upstream pipeline gate has already approved this text for extraction.
    Proceed with full extraction. Do NOT return empty arrays or skip extraction.
  - Extract the single most prominent or most completely described pathway in the text.
  - Focus on the pathway with the most detailed reaction steps, enzymes, and intermediates.
  - Set scope_warning to "" (empty).
  - Treat unrelated examples mentioned in passing the same way as out-of-scope reactions:
    set their scope_membership to "out_of_scope" or omit them.

Case B — document_type is "multi_example_review" AND selected_example is non-empty:
  - Extract ONLY entities and reactions whose evidence is locally anchored to the selected_example by paragraph, figure caption, or directly adjacent section.
  - Do NOT extract entities/reactions that belong to other named examples in the review even if they appear in the same document.
  - Apply the evidence-locality rule: an entity belongs to selected_example only if the entity name and a reaction/transformation involving it appear within the same paragraph or figure caption as the selected_example's name or product.

Case C — context_type is "enzyme_mechanism" or "partial_biosynthetic_step":
  - Do NOT attempt to extract a complete pathway.
  - Extract only the explicitly described reaction step(s), enzyme(s), substrate(s), and product(s).
  - Leave reactions, transports, and interactions lists containing only what is directly supported.
  - Do not infer upstream or downstream steps to complete the pathway.

Case D — document_type is "primary_research" or scope_clarity_score >= 0.7:
  - Proceed with normal full extraction.

If no <upstream_context> is supplied, proceed with normal extraction (Case D behavior).

CROSS-CUTTING CONSTRAINTS
- Partial pathway evidence should remain partial. Prefer unresolved warnings over invented pathway completion.
- Never resolve or assign an entity to a candidate of a different biological type solely because of confidence score. Type compatibility beats confidence.
- Named genes/proteins outrank generic enzyme class names. If both are present in text for the same activity, use the named gene/protein.
- Cofactors (PLP/pyridoxal phosphate, FAD, FMN, NAD+/NADH, NADP+/NADPH, SAM, CoA, ATP/ADP/AMP, heme, TPP, metal ions) are compounds/cofactors/ions, never reaction modifiers or enzymes. Include them in reactions only when stoichiometrically consumed or regenerated as inputs/outputs.
- Extraction layer: single enzymes are proteins. Use protein_complex only when the text explicitly names a complex, holoenzyme, heterodimer, or multisubunit structure.
- Export layer: PathWhiz/PWML export may wrap a protein catalyst in a generated single-protein protein_complex for reaction enzyme references. This technical wrapper is not an extracted biological claim and must never be applied to compounds, cofactors, ions, metabolites, or small molecules.
